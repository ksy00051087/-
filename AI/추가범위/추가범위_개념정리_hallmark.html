1

LLM 안전 정렬 (Safety Alignment)

HHH 원칙 · Red-teaming · Constitutional AI(RLAIF) · 안전-유용성 트레이드오프 · 안전 정렬 파이프라인

1-1안전 정렬이란?

정의 — LLM이 유해하거나 위험한 요청을 거부하고, 사회적으로 용인되는 가치와 규범에 부합하는 응답을 생성하도록 만드는 정렬(Alignment) 학습의 한 축. 앞서 배운 정렬 학습이 "지시를 잘 따르는가(지시 학습)"와 "더 나은 응답을 고르는가(선호 학습)"를 다뤘다면, 안전 정렬은 그중에서도 "해를 끼치지 않는가"에 초점을 맞춘 부분입니다.

HHH 원칙 (Anthropic)
  • Helpful (유용함) — 사용자의 목적을 실제로 도와야 한다.
  • Harmless (무해함) — 신체적·심리적·사회적 피해로 이어질 수 있는 응답을 하지 않는다.
  • Honest (정직함) — 모델이 알지 못하는 것을 아는 척하지 않고, 오해를 유발하는 응답을 하지 않는다.
Remark. 세 목표는 서로 충돌할 수 있습니다. 예를 들어 위험한 화학물질 제조법을 묻는 질문에 "유용하게" 답하면 "무해함"을 해칩니다. 안전 정렬 학습은 이 트레이드오프에서 무해함을 우선시하는 균형점을 찾는 과정입니다.

1-2Red-teaming (레드팀)

정의 — 모델을 배포하기 전, 일부러 유해한 응답을 유도하는 적대적 프롬프트를 시도해 취약점을 찾아내는 과정. 공격자의 관점에서 모델을 미리 "공격"해보고, 발견된 취약점을 다시 학습 데이터로 만들어 모델을 보강합니다.

  • 사람 red-teamer가 직접 탈옥(jailbreak) 프롬프트를 시도하는 수동 방식
  • 또 다른 LLM이 공격 프롬프트를 자동 생성하는 자동화된(Automated) red-teaming

Red-teaming에서 발견된 실패 사례는 안전 관련 선호 데이터(더 안전한 응답 vs 덜 안전한 응답 쌍)로 가공되어, 보상 모델(RM) 학습 데이터에 다시 포함됩니다 — 즉 안전 정렬은 선호 학습(RLHF) 파이프라인 위에서 이뤄지는 하나의 적용입니다.

1-3Constitutional AI (RLAIF)

사람이 일일이 "이 응답이 더 안전하다"고 라벨링하는 데는 비용과 한계가 있습니다. Constitutional AI는 사람이 만든 소수의 원칙("헌법", constitution)을 기준으로 모델 스스로 자기 응답을 비판하고 수정하게 한 뒤, 그 결과로 선호 데이터를 만드는 방법입니다.

1) 초기 응답 생성 2) 모델이 "헌법" 기준으로 자기 비판(critique) 3) 비판을 반영해 응답을 스스로 수정(revise) 4) 수정 전/후 응답 쌍 → AI 피드백 기반 선호 데이터 5) RLAIF(RL from AI Feedback)로 학습

Bai et al., Constitutional AI: Harmlessness from AI Feedback, Anthropic 2022

1-4안전-유용성 트레이드오프 (Over-refusal)

안전 정렬을 지나치게 강하게 걸면, 모델이 실제로는 무해한 질문까지 거절하는 과잉 거절(Over-refusal) 문제가 생깁니다. 예: "총을 쏘는 방법"이 아니라 "사진을 잘 찍는 방법"인데 단어만 보고 거절하는 경우.

정리 — 안전 정렬의 목표는 "무조건 거절"이 아니라, 해로운 요청만 정확히 걸러내면서 정당한 요청은 최대한 돕는 것입니다.

1-5안전 정렬 파이프라인 한눈에 보기

사전학습된 LLM │ ▼ 안전 관련 SFT 데이터로 지시 학습 (거절 예시 + 정상 응답 예시) │ ▼ Red-teaming으로 취약 프롬프트 수집 ──┐ │ │ ▼ ▼ Constitutional AI(RLAIF) 또는 사람 피드백으로 안전 선호 데이터 생성 │ ▼ 보상 모델(RM) 재학습 (안전성 반영) │ ▼ PPO 등 RLHF 강화학습으로 정렬 │ ▼ 배포 후 지속적인 red-teaming ↔ 재학습 (반복)
핵심 질문. 안전 정렬은 왜 "한 번 학습하면 끝"이 아니라 배포 이후에도 반복되는 과정일까?
탈옥(jailbreaking) 기법은 계속 새로 발견되고, 모델이 배포된 이후에도 사용자들이 새로운 우회 방법을 찾아내기 때문입니다. 그래서 안전 정렬은 Red-teaming → 재학습 → 재배포를 반복하는 지속적인 사이클로 운영됩니다.

개방형(Open)과 폐쇄형(Closed) LLM

정의와 구분 · 장단점 비교 · 접근 방법 · 선택 기준

2-1정의와 대표 예시

폐쇄형 (Closed)개방형 (Open-sourced / Open-weight)
정의모델 가중치·구조·학습 데이터가 비공개, API로만 접근 가능모델 가중치가 공개되어 누구나 다운로드·수정·재배포 가능
대표 예시ChatGPT(OpenAI), Claude(Anthropic), Gemini(Google)LLaMA(Meta), Gemma(Google), Qwen(Alibaba), DeepSeek, Mistral
접근 방법웹/앱, Playground, API 호출Hugging Face 허브 등에서 직접 다운로드 후 로컬/서버 실행

2-2폐쇄형의 장단점

  • 장점 — 일반적으로 더 우수한 성능, 최신 기능을 가장 먼저 사용, 별도 인프라 없이 바로 사용 가능
  • 단점 — API 호출마다 비용 발생, 모델 구조·학습 데이터·가중치가 비공개(블랙박스), 서비스 정책 변경에 종속됨

2-3개방형의 장단점

  • 장점 — 무료로 다운로드·사용 가능, 모델 구조·가중치 공개로 파인튜닝·경량화·온디바이스 배포에 자유로움, 데이터가 외부로 나가지 않아 보안·프라이버시에 유리
  • 단점 — 충분한 계산 자원(GPU)이 필요, 상대적으로 최상위 폐쇄형 모델보다 성능이 낮은 편(단, 격차는 빠르게 줄어드는 추세)

2-4어떤 상황에 어떤 선택이 맞을까?

고려 요소폐쇄형이 유리한 경우개방형이 유리한 경우
초기 비용인프라 구축 없이 바로 시작초기엔 GPU 투자가 필요하지만 장기적으로 API 비용 절감
데이터 민감도클라우드 전송이 허용되는 경우민감 데이터를 외부로 보낼 수 없는 경우(온프레미스)
커스터마이징제한적(프롬프트·파인튜닝 API 수준)가중치 수준의 자유로운 파인튜닝·경량화 가능
최신 성능최상위 벤치마크 성능이 필요한 경우온디바이스·저지연 등 배포 제약이 강한 경우
정리 — 개방형/폐쇄형은 "어느 쪽이 절대적으로 더 낫다"의 문제가 아니라, 비용·데이터 민감도·커스터마이징 자유도·성능 요구 수준이라는 네 가지 축의 트레이드오프입니다.
3

오버피팅과 분포 변화

과적합의 정의와 방지 기법 · 분포 변화(Distribution Shift)의 세 유형 · 둘의 관계

3-1오버피팅(과적합, Overfitting)

정의 — 모델이 학습 데이터의 패턴뿐 아니라 노이즈까지 과도하게 암기하여, 학습 데이터에서는 성능이 매우 높지만 새로운(테스트) 데이터에서는 성능이 크게 떨어지는 현상.

Underfitting(과소적합)적절한 적합Overfitting(과적합)
학습 오차높음낮음매우 낮음
검증/테스트 오차높음낮음높음(학습 오차와 격차 큼)
원인모델이 너무 단순함-모델이 너무 복잡하거나 데이터가 부족함
방지 기법
  • 정규화(Regularization) — L1/L2 페널티로 가중치 크기를 제한
  • Dropout — 학습 시 일부 뉴런을 무작위로 비활성화
  • Early Stopping — 검증 손실이 더 이상 줄지 않으면 학습 조기 종료
  • 데이터 증강(Data Augmentation) — 학습 데이터의 다양성을 인위적으로 늘림
  • 교차검증(Cross-validation) — 데이터를 여러 번 나눠 일반화 성능을 안정적으로 추정

3-2분포 변화 (Distribution Shift)

정의 — 모델을 학습시킨 데이터의 분포와 실제 배포 후 마주치는 데이터의 분포가 달라지는 현상. 학습 당시에는 성능이 좋았던 모델도, 분포가 변하면 성능이 저하될 수 있습니다.

유형변하는 것예시
Covariate Shift
(입력 분포 변화)		입력 $P(X)$의 분포낮에 찍은 사진으로 학습했는데, 배포 후 야간 사진이 많이 들어옴
Label Shift
(레이블 분포 변화)		출력 $P(Y)$의 분포학습 시엔 스팸 비율이 5%였는데, 실제 서비스에서는 스팸 비율이 30%로 증가
Concept Shift
(관계 자체 변화)		입력-출력 관계 $P(Y\mid X)$같은 리뷰 문장이라도 유행어의 의미가 바뀌어 감성 라벨링 기준이 달라짐

3-3오버피팅과 분포 변화의 관계

오버피팅된 모델은 학습 데이터의 특정 분포에만 지나치게 최적화되어 있기 때문에, 분포 변화가 일어났을 때 더 크게 흔들립니다. 즉 오버피팅이 심할수록 분포 변화에 대한 강건성(robustness)이 낮습니다.

핵심 질문. 검증 데이터 성능이 좋은 모델이 실제 서비스에서는 왜 성능이 떨어질 수 있을까?
검증 데이터가 학습 데이터와 같은 분포에서 뽑혔다면, 검증 성능은 "분포가 변하지 않는다"는 가정 아래의 성능일 뿐입니다. 실제 서비스 데이터의 분포가 학습/검증 분포와 다르면(분포 변화), 검증 성능이 좋아도 실제 성능은 떨어질 수 있습니다.

3-4대응 방법

  • 지속적 모니터링 — 배포 후에도 입력·출력 분포를 지속적으로 관찰
  • 주기적 재학습(Retraining) — 최신 데이터를 반영해 모델을 다시 학습
  • 도메인 적응(Domain Adaptation) — 목표 분포에 맞춰 모델을 미세조정
정리 — 오버피팅은 "학습 시점"의 일반화 실패, 분포 변화는 "배포 이후 시점"의 일반화 실패입니다. 둘 다 "모델이 보지 못한 데이터에 얼마나 잘 대응하는가"라는 같은 문제의식에서 출발합니다.
4

온디바이스 VLM (On-device Vision-Language Model)

필요성 · VLM 기본 구조 · 경량화 기법(양자화·지식 증류·가지치기) · 트레이드오프

4-1온디바이스 VLM이란?

정의 — 클라우드 서버가 아니라 스마트폰·태블릿 등 자원이 제한된 단말기(모바일 GPU/NPU)에서 직접 실행되는, 이미지와 텍스트를 함께 이해하는 경량 비전-언어 모델(VLM).

필요한 이유
  • 프라이버시 — 사진·화면 등 민감한 데이터를 서버로 전송하지 않고 기기 안에서만 처리
  • 지연시간(Latency) — 네트워크 왕복 없이 즉시 응답 → 실시간 상호작용에 유리
  • 오프라인 사용 — 인터넷 연결이 없는 환경에서도 동작
  • 비용 — 서버 추론 비용(API 과금)이 들지 않음

4-2VLM의 기본 구조

이미지 → [ 이미지 인코더 ] (예: CLIP ViT) │ ▼ [ Projection Layer ] (이미지 임베딩 → LLM 임베딩 공간으로 정렬) │ ▼ 텍스트 프롬프트 + 이미지 임베딩 → [ LLM(Decoder) ] → 텍스트 응답

온디바이스 VLM도 큰 틀에서는 이미지 인코더 + LLM 구조를 따르되, 두 구성 요소를 모두 모바일 환경에서 돌아갈 만큼 작게 만든 버전입니다.

4-3경량화 기법

  • 양자화(Quantization) — 32비트 부동소수점 가중치를 8비트·4비트 정수 등으로 낮춰 모델 크기와 연산량을 줄임
  • 지식 증류(Knowledge Distillation) — 크고 성능 좋은 teacher 모델의 출력을 작은 student 모델이 모방하도록 학습시켜 성능은 최대한 유지하면서 크기를 줄임
  • 가지치기(Pruning) — 중요도가 낮은 가중치·뉴런·어텐션 헤드를 제거
  • 효율적 아키텍처 설계 — MobileViT, 경량 CNN 백본 등 처음부터 적은 연산으로 동작하도록 설계된 구조 사용

4-4트레이드오프와 사례

축클라우드 VLM온디바이스 VLM
정확도높음(대형 모델)상대적으로 낮음(경량화로 인한 손실)
지연시간네트워크 왕복 필요즉시 응답
프라이버시서버 전송 필요기기 내 처리로 유리
배터리/발열기기 부담 없음연산 부담이 기기로 이전

참 함수와 측정오차

지도학습의 기본 가정 · 참 함수 f · 측정오차(비가역 오차) · 지도학습의 목적 · 오차의 분해

5-1지도학습의 기본 가정

지도학습은 데이터가 어떤 알 수 없는 참 함수(true function) $f$ 에 측정오차(measurement error) $\varepsilon$ 이 더해진 형태로 생성된다고 가정합니다.

$$Y = f(X) + \varepsilon$$
  • 참 함수 $f$ — 입력 $X$가 주어졌을 때 출력 $Y$가 결정되는 실제(이상적인) 관계. 우리는 이 함수를 직접 알 수 없고, 데이터로부터 추정할 뿐입니다.
  • 측정오차 $\varepsilon$ — $X$만으로는 설명되지 않는 무작위 잡음(random noise). 평균이 0인 확률변수로 가정하는 경우가 많습니다($E[\varepsilon]=0$).

5-2지도학습의 목적

지도학습의 목적은 관측된 데이터 $(X_i, Y_i)$로부터, 참 함수 $f$를 최대한 잘 근사하는 추정 함수(estimated function) $\hat f$ 를 찾는 것입니다.

$$\hat Y = \hat f(X)$$

여기서 $\hat f$가 아무리 좋아도, $\varepsilon$에서 비롯된 오차는 원리적으로 제거할 수 없습니다 — 모델을 개선하는 문제와 무관한 오차이기 때문입니다.

5-3측정오차는 왜 "줄일 수 없는" 오차인가

측정오차 $\varepsilon$은 $X$에 담기지 않은 정보(관측되지 않은 변수, 측정 장비의 한계, 본질적인 무작위성 등)에서 비롯됩니다. 그래서 이를 비가역 오차(irreducible error)라고도 부릅니다.

Remark. "모델을 더 복잡하게 만들면 오차를 0으로 줄일 수 있다"는 생각은 틀렸습니다. $\hat f$를 아무리 $f$에 가깝게 만들어도, $\varepsilon$에서 비롯된 오차는 그대로 남습니다.

5-4기대 예측오차의 분해

임의의 새로운 입력 $x_0$에서, 추정 함수 $\hat f$의 기대 예측오차(Expected Prediction Error)는 다음과 같이 세 항으로 분해됩니다.

$$E\left[(Y-\hat f(x_0))^2\right] \;=\; \underbrace{\left(\mathrm{Bias}[\hat f(x_0)]\right)^2}_{\text{편향}^2} \;+\; \underbrace{\mathrm{Var}[\hat f(x_0)]}_{\text{분산}} \;+\; \underbrace{\mathrm{Var}[\varepsilon]}_{\text{비가역 오차}}$$
항의미줄이는 방법
편향² (Bias²)$\hat f$가 참 함수 $f$를 얼마나 잘못 근사하는가(모형이 너무 단순할 때 큼)모델 복잡도를 높임(단, 분산 증가 위험)
분산 (Variance)학습 데이터가 바뀔 때마다 $\hat f$가 얼마나 크게 흔들리는가(모형이 너무 복잡할 때 큼)정규화, 데이터 추가, 모델 단순화
비가역 오차측정오차 $\varepsilon$ 자체의 분산줄일 수 없음 — 모델과 무관한 데이터 자체의 한계
핵심 질문. "편향-분산 트레이드오프"에서 아무리 최적의 모델을 골라도 예측오차가 0이 될 수 없는 이유는?
편향²과 분산은 모델 선택으로 줄일 수 있지만, 비가역 오차(측정오차의 분산)는 데이터 생성 과정 자체에 내재된 무작위성이라 모델을 아무리 개선해도 남습니다. 즉 예측오차의 하한선은 비가역 오차로 결정됩니다.

이 문서의 큰 줄기

다섯 주제는 각각 독립적이지만 하나의 흐름으로도 읽힙니다. LLM을 안전하게(1) 그리고 어떤 형태로(2) 쓸 것인가는 배포 단계의 질문이고, 모델이 학습·배포 환경에서 얼마나 일반화되는가(3)와 얼마나 가벼운 환경에서도 동작하는가(4)는 실무 적용의 질문이며, 그 모든 것의 밑바탕에는 지도학습이 애초에 무엇을 추정하려는 것인가(5)라는 통계적 기본기가 깔려 있습니다.
