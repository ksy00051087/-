학습 시작 — 정보는 어떻게 저장되고 있을까?

Onboarding · 학습 목표

"데이터를 잘 정리해 두어야 빠르게 찾고 안전하게 관리할 수 있습니다."

책을 아무 데나 쌓아두면 필요한 책을 찾기 어렵기 때문에 주제별·작가별로 분류해 책장에 정리합니다. 컴퓨터도 수많은 정보를 빠르게 찾고 효율적으로 관리하려면 잘 정리된 책장처럼 데이터를 구조적으로 저장해야 하고, 이 역할을 하는 것이 데이터베이스입니다.

학습 목표
  • 데이터베이스의 개념과 등장 배경을 이해한다.
  • 관계형 데이터베이스(RDB)의 구조와 테이블 간의 관계를 설명할 수 있다.
  • SQL의 기본 구조와 문법을 이해한다.
  • SELECT, FROM, WHERE, ORDER BY 문을 활용해 데이터를 조회할 수 있다.
  • DISTINCT, LIMIT, LIKE 등의 키워드를 사용하여 원하는 조건으로 데이터를 필터링할 수 있다.
  • GROUP BY와 HAVING을 활용한 집계 데이터를 조회할 수 있다.
  • SQL 실행 순서를 이해하고 각 절의 역할을 구분할 수 있다.

Database

데이터 · 데이터 사용량 증가 · 저장 방식 비교 · 데이터베이스 역할

1-1Database란?

체계적으로 정리된 데이터의 모음. 컴퓨터가 많은 정보를 빠르게 찾고 효율적으로 관리하도록 데이터를 구조적으로 저장합니다.

1-2데이터 (Data)

저장이나 처리를 위해 변환된 정보. 우리가 표현한 정보를 컴퓨터가 다룰 수 있도록 구조화한 것으로, 분석·계산·저장을 위해 정보를 구체적인 형태로 정리한 것입니다. 예: "서울", 25, True

1-3증가하는 데이터 사용량

  • 배달의민족 — 2022년 한 해 동안 1억 100만 건 이상의 주문 처리
  • 유튜브 — 1분마다 500시간 이상의 새 동영상 업로드
  • 넷플릭스 — 구독자 3억 명 돌파(2024), 2025년 상반기 전 세계 시청 시간 약 950억 시간
  • IBM — 전 세계 모든 데이터의 약 90%는 2015년 이후 생산
  • 데이터 센터 성장 — 네이버 제2데이터센터 6,500억 원(2020), 카카오 1·2데이터센터 1.5조 원(2022). 전 세계 시장은 2024~2029년 연평균 약 11% 성장 전망(Mordor Intelligence)

→ 데이터를 잘 저장하고 잘 관리하여 활용할 수 있는 기술이 중요해짐

1-4기존의 데이터 저장 방식

방식장점한계
파일(File) 이용어디에서나 쉽게 사용 가능 (예: 이름·나이·사는 곳을 txt에 나열)데이터를 구조적으로 관리하기 어려움
스프레드시트(Spreadsheet) 이용테이블의 열과 행을 사용해 데이터를 구조적으로 관리 가능크기 제한(일반적으로 약 100만 행), 보안(파일·링크 소유 여부에 따른 단순 접근 권한), 정확성(값이 바뀌면 모든 위치를 찾아 직접 수정해야 하고, 여러 시트에 분산되어 있으면 변경 누락·추가 문제 발생)
데이터베이스의 역할 — 데이터를 저장(구조적 저장)하고 조작(CRUD: Create · Read · Update · Delete)하는 것
2

Relational Database

관계형 데이터베이스 · 예시 · 6가지 키워드 · DBMS · RDBMS · SQLite

2-1관계형 데이터베이스 (Relational Database)

데이터 간에 관계가 있는 데이터 항목들의 모음. 테이블·행·열의 정보를 구조화하는 방식이며, 서로 관련된 데이터 포인터를 저장하고 이에 대한 액세스를 제공합니다.

병원 접수창구 비유 — 환자 정보와 진료 기록이 서로 다른 종이에 적혀 있으면 동명이인을 구별할 수 없습니다. 그래서 환자마다 고유한 번호(환자번호)를 부여하고 진료 기록에 그 번호를 함께 적어 정확히 연결합니다.

각각의 테이블에 나누어 저장— 공통된 키 값 —테이블 간 (논리적) 연결→필요할 때 함께 조회·조작

이 관계 덕분에 두 테이블을 사용해 데이터를 다양한 형식으로 조회할 수 있습니다. 예: 특정 날짜에 구매한 모든 고객 조회, 지난 달에 배송이 지연된 고객 조회 등.

2-2관계형 데이터베이스 예시 (1~2/4)

id이름청구지주소지
1김한웅서울강원
2유미선강원경기
3박지수경기서울

고객 데이터 간 비교에는 무엇을 써야 할까? 이름이나 주소는 동명이인·같은 주소지가 있을 수 있음 → 각 데이터에 고유한 식별 값을 부여(기본 키, Primary Key). 주민등록번호처럼 사람마다 다른 값.

2-3관계형 데이터베이스 예시 (3~4/4)

id주문일주문 상태고객 ID
12002/01/01배송완료3
22002/03/04상품준비중3
32002/02/03배송중1

누가 어떤 주문을 했는지 어떻게 식별할까? → 주문 정보에 고객의 고유한 식별 값(고객 ID)을 저장(외래 키, Foreign Key). 예: 박지수(id 3)는 주문 1·2를, 김한웅(id 1)은 주문 3을 했음.

2-4관계형 데이터베이스 관련 키워드 6가지

키워드다른 이름의미
1. TableRelation데이터를 기록하는 곳
2. FieldColumn, Attribute각 필드에는 고유한 데이터 형식(타입)이 지정됨
3. RecordRow, Tuple각 레코드에는 구체적인 데이터 값이 저장됨
4. DatabaseSchema테이블의 집합
5. Primary Key기본 키, PK각 레코드의 고유한 값. 관계형 데이터베이스에서 레코드의 식별자로 활용
6. Foreign Key외래 키, FK테이블의 필드 중 다른 테이블의 레코드를 식별할 수 있는 키. 다른 테이블의 기본 키를 참조하며, 각 레코드에서 서로 다른 테이블 간의 관계를 만드는 데 사용

2-5DBMS (Database Management System)

데이터베이스를 관리하는 소프트웨어 프로그램. 컴퓨터 속 "정리된 서류함" 역할 — 데이터를 일정한 규칙으로 저장하고, 필요할 때 쉽게 꺼내거나 바꿀 수 있도록 도와줍니다.

  • 데이터 저장 및 관리를 용이하게 하는 시스템
  • 데이터베이스와 사용자 간의 인터페이스 역할
  • 사용자가 데이터 구성, 업데이트, 모니터링, 백업, 복구 등을 할 수 있도록 도움

2-6RDBMS (Relational DBMS)

관계형 데이터베이스를 관리하는 소프트웨어 프로그램. 도서관 대출 시스템처럼 도서 목록·회원 명단·대출 내역을 각각 따로 두되, 회원 번호와 책 번호로 연결합니다 — 데이터를 여러 테이블에 나누어 저장하고 공통된 키로 '관계'를 맺어 함께 사용하게 해 주는 시스템.

서비스 종류: SQLite, MySQL, PostgreSQL, Oracle Database 등. 모두 SQL 기반이지만 세부 기능·사용 방식이 다르므로 프로젝트 목적과 환경에 맞는 도구를 고르는 것이 중요합니다.

2-7SQLite

  • 경량의 오픈 소스 데이터베이스 관리 시스템
  • 설치 없이 가볍게 실행 가능해 모바일 앱이나 소규모 프로그램에 적합
  • 컴퓨터나 모바일 기기에 내장되어 간단하고 효율적인 데이터 저장에 사용

2-8데이터베이스 정리

  • Table은 데이터가 기록되는 곳
  • Table에는 행에서 고유하게 식별 가능한 기본 키라는 속성이 있으며, 외래 키를 사용해 각 행에서 서로 다른 테이블 간의 관계를 만들 수 있음
  • 데이터는 기본 키 또는 외래 키를 통해 결합(join)될 수 있는 여러 테이블에 걸쳐 구조화됨
3

SQL

Structured Query Language · Syntax · SQL Statements · 4가지 유형

3-1SQL (Structured Query Language)

데이터베이스에 정보를 저장하고 처리하기 위한 프로그래밍 언어. 테이블 형태로 구조화된 관계형 데이터베이스에게 요청을 질의(요청)합니다.

도서관 사서에게 내는 요청서 비유 — "2000년 이후 출판된 과학 소설을 최신순으로 정렬해서 찾아주세요"처럼 사람이 쓰는 모호한 말 대신, DBMS(사서)에게 정해진 양식에 따라 정확한 요청을 전달하는 언어가 SQL입니다.

3-2SQL Syntax

SELECT column_name FROM table_name;
  1. SQL 키워드는 대소문자를 구분하지 않음 — 하지만 대문자로 작성하는 것을 권장 (명시적 구분)
  2. 각 SQL Statement의 끝에는 세미콜론(;)이 필요 — 각 SQL Statement를 구분하는 방법 (명령어의 마침표)

3-3SQL Statements

SQL을 구성하는 가장 기본적인 코드 블록.

SELECT column_name FROM table_name;
  • 해당 예시 코드는 SELECT Statement라 부름
  • 이 Statement는 SELECT, FROM 2개의 keyword로 구성됨

3-4수행 목적에 따른 SQL Statements 4가지 유형

유형역할SQL 키워드
DDL (Data Definition Language)데이터의 기본 구조 및 형식 변경CREATE, DROP, ALTER
DQL (Data Query Language)데이터 검색SELECT
DML (Data Manipulation Language)데이터 조작 (추가, 수정, 삭제)INSERT, UPDATE, DELETE
DCL (Data Control Language)데이터 및 작업에 대한 사용자 권한 제어COMMIT, ROLLBACK, GRANT, REVOKE
단순히 SQL 문법을 암기하고 실행만 하는 것이 아니라, 관계형 데이터베이스를 잘 이해하고 다루는 방법을 학습하는 것이 목표입니다.

Querying · Sorting data

Database Client 연결 · SELECT 활용 1~5 · ORDER BY 활용 1~4 · NULL 정렬 · 실행 순서

4-1실습 준비 — Database 연결

VSCode 확장 Database Client(database-client.com, MariaDB/SQLite 관리·SQL 실행 지원)를 설치하고 실습용 sample.sqlite3 DB를 연결합니다. 설치·사용 가이드는 공용 노션 문서(「VSCode Database Client 설치 및 사용 가이드 (for SQLite)」)를 참고합니다. 실습 DB는 employees · customers · tracks 등의 테이블이 있는 음원 판매 샘플(Chinook) 데이터입니다.

4-2SELECT statement

테이블에서 데이터를 조회하는 DQL 구문.

SELECT
  select_list
FROM
  table_name;
  • SELECT 키워드 이후 데이터를 선택하려는 필드를 하나 이상 지정
  • FROM 키워드 이후 데이터를 선택하려는 테이블의 이름을 지정

4-3SELECT 활용 1~3

-- 1. employees에서 LastName 필드의 모든 데이터 조회
SELECT LastName FROM employees;

-- 2. LastName, FirstName 필드의 모든 데이터 조회
SELECT LastName, FirstName FROM employees;

-- 3. 모든 필드 데이터 조회
SELECT * FROM employees;

4-4SELECT 활용 4 — 별칭 AS

-- FirstName이 아닌 '이름'으로 출력
SELECT
  FirstName AS '이름'
FROM
  employees;

4-5SELECT 활용 5 — 산술 연산

-- tracks의 Name, Milliseconds 조회
-- (Milliseconds는 60000으로 나눠 분 단위로 출력)
SELECT
  Name,
  Milliseconds / 60000 AS '재생 시간(분)'
FROM
  tracks;
정수끼리 나누면 소수점이 버려집니다. 소수점까지 보려면 60000.0으로 나눕니다.

4-6SELECT 정리

  • 테이블의 데이터를 조회 및 반환
  • *(asterisk)를 사용하여 모든 필드 선택

4-7ORDER BY statement

조회 결과의 레코드를 정렬.

SELECT
  select_list
FROM
  table_name
ORDER BY
  column1 [ASC|DESC],
  column2 [ASC|DESC],
  ...;
  • FROM clause 뒤에 위치
  • 하나 이상의 컬럼을 기준으로 결과를 오름차순(ASC, 기본 값), 내림차순(DESC)으로 정렬

4-8ORDER BY 활용 1~2

-- 1. FirstName을 오름차순으로 조회
SELECT FirstName
FROM employees
ORDER BY FirstName;

-- 2. FirstName을 내림차순으로 조회
SELECT FirstName
FROM employees
ORDER BY FirstName DESC;

4-9ORDER BY 활용 3 — 여러 기준

-- customers에서 Country 내림차순 정렬 후,
-- 같은 Country 안에서는 City 오름차순
SELECT
  Country, City
FROM
  customers
ORDER BY
  Country DESC,
  City;

결과: United Kingdom(Edinburgh, London, London) → USA(Boston, Chicago, Cupertino …) 순.

4-10ORDER BY 활용 4 — 계산 결과 정렬

-- Milliseconds 내림차순 정렬 후 Name, 분 단위 재생 시간 조회
SELECT
  Name,
  Milliseconds / 60000 AS '재생 시간(분)'
FROM
  tracks
ORDER BY
  Milliseconds DESC;

결과 상위: Occupation / Precipice(88), Through a Looking Glass(84), Greetings from Earth, Pt.1(49) …

4-11정렬에서의 NULL

NULL 값이 존재할 경우 오름차순 정렬 시 결과에 NULL이 먼저 출력됩니다.

SELECT ReportsTo
FROM employees
ORDER BY ReportsTo;
-- (NULL), 1, 1, 2, 2, 2, 6, 6
NULL의 정렬 위치는 DBMS마다 다를 수 있습니다 (SQLite는 가장 작은 값으로 취급).

4-12SELECT statement 실행 순서 (지금까지)

FROM→SELECT→ORDER BY

테이블에서(FROM) 조회하여(SELECT) 정렬(ORDER BY)

Filtering data

Clause · DISTINCT · WHERE 활용 1~10 · Operators · Wildcards · LIMIT · OFFSET

5-1Filtering data 관련 Keywords

5-5WHERE 활용 1~2 — 같음 / 다름

5-6WHERE 활용 3~4 — IS NULL · AND / OR

-- 3. Company가 NULL이고 Country가 'USA'
SELECT LastName, FirstName, Company, Country
FROM customers
WHERE Company IS NULL
  AND Country = 'USA';

-- 4. Company가 NULL이거나 Country가 'USA'
SELECT LastName, FirstName, Company, Country
FROM customers
WHERE Company IS NULL
  OR Country = 'USA';

4번 결과에는 Company가 NULL인 다른 나라 고객(Germany, Canada…)과 회사가 있는 USA 고객(Google Inc., Microsoft Corporation…)이 모두 포함됩니다.

FROM tracks

-- 6. 위 결과를 Bytes 기준 오름차순

FROM tracks
WHERE Bytes BETWEEN 100000 AND 500000
ORDER BY Bytes;

6-1GROUP BY statement

6-2집계 함수 (Aggregation Functions)

값에 대한 계산을 수행하고 단일한 값을 반환하는 함수.

SUM, AVG, MAX, MIN, COUNT

-- 예시 1: Country로 그룹화 (중복 없이 나라 목록)

6-3GROUP BY 활용 1 — 그룹별 평균

-- tracks를 Composer로 그룹화해 Bytes 평균을 내림차순
SELECT
  Composer,
  AVG(Bytes)
FROM
  tracks
GROUP BY
  Composer
ORDER BY
  AVG(Bytes) DESC;

-- 별칭을 쓰면 정렬도 간결하게
SELECT
  Composer,
  AVG(Bytes) AS avgOfBytes
FROM tracks
GROUP BY Composer
ORDER BY avgOfBytes DESC;

6-4GROUP BY 활용 2 — 그룹 조건은 HAVING

-- Composer별 분 단위 재생 시간 평균이 10 미만인 그룹
-- ❌ WHERE에 집계 결과를 쓰면 에러
SELECT
  Composer,
  AVG(Milliseconds / 60000) AS avgOfMinute
FROM tracks
WHERE avgOfMinute < 10
GROUP BY Composer;
-- misuse of aggregate: AVG()

-- ✅ HAVING 사용
SELECT
  Composer,
  AVG(Milliseconds / 60000) AS avgOfMinute
FROM tracks
GROUP BY Composer
HAVING avgOfMinute < 10;

6-5HAVING clause

집계 항목에 대한 세부 조건을 지정. 주로 GROUP BY와 함께 사용하며, GROUP BY가 없다면 WHERE처럼 동작합니다.

WHEREHAVING
대상개별 행에 대한 조건GROUP BY에 의해 그룹화된 결과에 대한 조건
적용 시점FROM·JOIN 등의 단계 이후, GROUP BY 이전에 조건을 지정해 데이터를 필터링그룹화 이후, 그룹별 집계 결과에 조건을 걸어 특정 그룹만 선택
쓰임특정 조건을 만족하는 행만을 대상으로 집계·정렬 등의 작업을 수행할 때그룹별 집계 결과에 조건을 걸어 특정 그룹만을 선택할 때
예SELECT * FROM employees WHERE salary > 30000;SELECT department, COUNT(*) FROM employees GROUP BY department HAVING COUNT(*) > 5;

6-6SELECT statement 실행 순서 (전체)

FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT

테이블에서(FROM) 특정 조건에 맞추어(WHERE) 그룹화하고(GROUP BY), 그룹 중에서 조건이 있다면 맞추고(HAVING), 조회하여(SELECT) 정렬하고(ORDER BY), 특정 위치의 값을 가져옴(LIMIT).

작성 순서(SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT)와 실행 순서가 다릅니다. WHERE는 SELECT보다 먼저 실행되므로 SELECT에서 만든 별칭이나 집계 결과를 WHERE에서 쓸 수 없습니다.

6-9NULL 비교 — SQL의 3값 논리

NULLSQL의 3값 논리
SQL에서 NULL은 실제 값이 아니라 "값이 없음" 또는 "알 수 없음"을 의미. 그래서 일반 등호(=)로 비교하면 의도대로 작동하지 않음. 예: NULL = NULL의 결과는 TRUE가 아니라 UNKNOWN — 두 NULL이 실제로 어떤 값을 가지고 있지 않기 때문SQL은 논리 연산에 세 가지 값을 사용: 1. TRUE 2. FALSE 3. UNKNOWN(알 수 없음)
값의 부재와 불확실성 — NULL은 "값이 존재하지 않음"이므로 특정 값과 동일하다고 볼 수 없음. = 연산자를 쓰면 결과가 UNKNOWN이 되어 기대한 결과를 얻지 못함명시적 비교: IS와 IS NOT — SQL 표준은 NULL 비교에 IS NULL / IS NOT NULL을 쓰도록 규정. WHERE column IS NULL은 값이 없는 행을, WHERE column IS NOT NULL은 값이 존재하는 행을 정확히 찾음
-- = : 일반 값 비교
SELECT * FROM employees
WHERE department = 'Sales';

-- IS : NULL·Boolean 같은 특별한 값 비교
SELECT * FROM employees
WHERE department IS NULL;

SELECT * FROM employees
WHERE is_active IS TRUE;

8-5제약 조건 (Constraint)

테이블의 필드에 적용되는 규칙 또는 제한 사항. 데이터의 무결성을 유지하고 데이터베이스의 일관성을 보장합니다.

대표 제약 조건 3가지
  • PRIMARY KEY — 해당 필드를 기본 키로 지정
  • NOT NULL — 해당 필드에 NULL 값을 허용하지 않도록 지정
  • FOREIGN KEY — 다른 테이블과의 외래 키 관계를 정의

8-6AUTOINCREMENT keyword

자동으로 고유한 정수 값을 생성하고 할당하는 필드 속성 — 필드의 자동 증가를 나타내는 특수한 키워드로, 주로 primary key 필드에 적용합니다.

  • INTEGER PRIMARY KEY AUTOINCREMENT가 작성된 필드는 항상 새로운 레코드에 대해 이전 최대 값보다 큰 값을 할당
  • 삭제된 값은 무시되며 재사용할 수 없게 됨
AUTOINCREMENT는 INTEGER PRIMARY KEY에만 사용할 수 있습니다 (INT, BIGINT로 쓰면 에러).

10-1관계의 필요성

  1. 커뮤니티 게시판에 필요한 데이터(게시글 id·제목·내용·작성자·역할 …)를 한 테이블에 모두 넣으면, '하석주'가 작성한 모든 게시글은 SELECT * FROM 테이블 WHERE writer = '하석주';로 찾을 수 있지만 — 동명이인이 있거나 이름이 바뀌면 문제가 생깁니다.
  2. 그래서 테이블을 나누어서 분류합니다: articles(게시글) · users(회원) · roles(역할: admin, staff, student).
  3. articles와 users 테이블에 각각 userId, roleId 외래 키 필드를 작성합니다.
    • 관리자인 사람만 보고 싶다면? → roleId가 1인 데이터 조회
    • 하석주가 권미숙으로 개명한다면? → users에서 한 번만 변경하면 자동으로 모두 반영
테이블을 나누는 이유는 데이터 중복을 줄이고 수정·삭제를 쉽게 하기 위해서입니다 (예: 사용자 정보와 주문 정보는 분리). 하지만 실제로는 사용자 정보와 주문 내용을 함께 보여줘야 하는 상황이 많으므로 나눠진 테이블을 다시 묶어야 하는데, 그 방법이 바로 JOIN입니다.

10-2JOIN clause

10-6INNER JOIN — 일치하는 레코드만

두 테이블에서 값이 일치하는 레코드에 대해서만 결과를 반환 (교집합).

SELECT
  select_list
FROM
  table_a
INNER JOIN table_b
  ON table_b.fk = table_a.pk;
  • FROM 절 이후 메인 테이블 지정 (table_a)
  • INNER JOIN 절 이후 메인 테이블과 조인할 테이블 지정 (table_b)
  • ON 키워드 이후 조인 조건 작성 — table_a와 table_b 간의 레코드를 일치시키는 규칙을 지정

10-7INNER JOIN 예시 · 활용

-- 작성자가 있는(존재하는 회원) 모든 게시글을 작성자 정보와 함께 조회
SELECT * FROM articles
INNER JOIN users
  ON users.id = articles.userId;
-- 제목4(userId 4)는 users에 4번이 없어 결과에서 빠짐

-- 1번 회원(하석주)이 작성한 모든 게시글의 제목과 작성자명
SELECT articles.title, users.name
FROM articles
INNER JOIN users
  ON users.id = articles.userId
WHERE users.id = 1;
-- 제목1 하석주 / 제목3 하석주 / 제목5 하석주

10-8LEFT JOIN — 왼쪽은 전부

오른쪽 테이블의 일치하는 레코드와 함께 왼쪽 테이블의 모든 레코드 반환.

SELECT
  select_list
FROM
  table_a
LEFT JOIN table_b
  ON table_b.fk = table_a.pk;
  • FROM 절 이후 왼쪽 테이블 지정 (table_a)
  • LEFT JOIN 절 이후 오른쪽 테이블 지정 (table_b)
  • ON 키워드 이후 조인 조건 작성
  • 왼쪽 테이블의 모든 레코드를 유지하고, ON 조건에 맞는 오른쪽 레코드를 붙임 (없으면 NULL)

10-9LEFT JOIN 예시 · 활용

  ON users.id = articles.userId;

11-1타입 선호도 (Type Affinity)

컬럼에 데이터 타입이 명시적으로 지정되지 않았거나 지원하지 않을 때 SQLite가 자동으로 데이터 타입을 추론하는 것. 선언한 타입 이름에 따라 다음 다섯 가지 affinity 중 하나가 정해집니다.

선언한 타입 이름 예시 (CREATE TABLE / CAST)결과 Affinity
INT, INTEGER, TINYINT, SMALLINT, MEDIUMINT, BIGINT, UNSIGNED BIG INT, INT2, INT8INTEGER
CHARACTER(20), VARCHAR(255), VARYING CHARACTER(255), NCHAR(55), NATIVE CHARACTER(70), NVARCHAR(100), TEXT, CLOBTEXT
BLOB, 타입 미지정BLOB
REAL, DOUBLE, DOUBLE PRECISION, FLOATREAL
NUMERIC, DECIMAL(10,5), BOOLEAN, DATE, DATETIMENUMERIC

https://www.sqlite.org/datatype3.html

타입 선호도 존재 이유
  1. 유연한 데이터 타입 지원 — 데이터 타입을 명시적으로 지정하지 않고도 데이터를 저장하고 조회할 수 있음. 컬럼에 저장되는 값의 특성을 기반으로 데이터 타입을 유추
  2. 간편한 데이터 처리 — INTEGER Type Affinity를 가진 열에 숫자 모양의 문자열('123')을 넣으면 숫자로 변환하여 저장 (숫자로 바꿀 수 없는 문자열은 그대로 저장)
  3. SQL 호환성 — 다른 데이터베이스 시스템과 호환성을 유지

11-2반드시 NOT NULL 제약을 사용해야 할까?

"NO" — 하지만 데이터베이스를 사용하는 프로그램에 따라 NULL을 저장할 필요가 없는 경우가 많으므로 대부분 NOT NULL을 정의합니다.

  • "값이 없다"는 표현을 테이블에 기록하는 것은 '0'이나 '빈 문자열' 등을 사용하는 것으로 대체하는 것을 권장 — 문자열 컬럼은 빈 문자열('')로 대체하는 경우가 많음
  • 숫자나 날짜처럼 0이 실제 의미를 가지는 컬럼은 NULL을 허용하는 것이 자연스러움

11-3SQLite의 날짜와 시간

  • SQLite에는 날짜 및/또는 시간을 저장하기 위한 별도 데이터 타입이 없음
  • 대신 날짜 및 시간에 대한 함수를 사용해 표기 형식에 따라 TEXT, REAL, INTEGER 값으로 저장

DB SQL 01 — 조회 (11/02 오전, 슬라이드 153장)

개념설명예시

관계형 데이터베이스관련 있는 데이터를 테이블 형태로 저장하고 키로 연결하는 데이터베이스고객 테이블과 주문 테이블을 고객 ID로 연결

이 문서의 큰 줄기

  • 파일·스프레드시트의 한계(구조·크기·보안·정확성) 때문에 데이터를 테이블로 나누고 PK·FK로 관계를 맺는 RDB가 쓰인다. 이를 관리하는 소프트웨어가 RDBMS(SQLite 등).
  • SQL은 RDBMS에 정확한 요청을 보내는 언어. 목적에 따라 DDL · DQL · DML · DCL 네 유형.
  • 조회의 뼈대: SELECT(무엇을) · FROM(어디서) · WHERE(조건) · GROUP BY/HAVING(묶고 거르기) · ORDER BY(정렬) · LIMIT(개수).
  • 실행 순서는 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. 그래서 집계 조건은 WHERE가 아닌 HAVING에 쓴다.
  • NULL은 값이 아님 — = 대신 IS NULL / IS NOT NULL로 비교한다 (3값 논리).

DB SQL 02 — 테이블·데이터 관리와 JOIN (11/02 오후, 슬라이드 113장)

개념설명예시
CREATE TABLE새로운 테이블을 생성하는 SQL 명령어CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT);
INSERT테이블에 새 데이터를 삽입하는 명령어INSERT INTO users (name) VALUES ('하석주');
SELECT테이블에서 데이터를 조회하는 명령어SELECT * FROM users;
UPDATE기존 데이터를 수정하는 명령어UPDATE users SET name = '김민수' WHERE id = 1;
DELETE테이블의 데이터를 삭제하는 명령어DELETE FROM users WHERE id = 1;
ALTER TABLE테이블 구조를 변경하는 명령어ALTER TABLE users ADD COLUMN age INTEGER;
DROP TABLE테이블 자체를 삭제하는 명령어DROP TABLE users;
PRIMARY KEY각 행을 고유하게 식별하는 기본 키id INTEGER PRIMARY KEY
FOREIGN KEY다른 테이블의 기본 키를 참조하는 외래 키FOREIGN KEY (userId) REFERENCES users(id)
NOT NULL해당 열에 반드시 값이 있어야 함을 나타내는 제약조건name TEXT NOT NULL
INNER JOIN / LEFT JOIN일치하는 행만 / 왼쪽 테이블 전체 + 일치하는 오른쪽 행... INNER JOIN users ON users.id = articles.userId

이 문서의 큰 줄기

  • DDL로 그릇을 만든다: CREATE TABLE(타입 + 제약 조건 + AUTOINCREMENT) → ALTER TABLE(ADD/RENAME/DROP COLUMN, RENAME TO) → DROP TABLE.
  • DML로 내용을 바꾼다: INSERT(한 개·여러 개·DATE()) / UPDATE·DELETE는 WHERE가 없으면 전체 레코드에 적용된다. 서브쿼리로 "오래된 2개"처럼 대상을 고를 수 있다.
  • 테이블을 나누고 FK로 잇고 JOIN으로 다시 묶는다: INNER JOIN은 짝이 있는 것만, LEFT JOIN은 왼쪽 전부(짝 없으면 NULL). LEFT JOIN + IS NULL = "~한 적 없는 것".
  • SQLite의 특성: VARCHAR 길이를 검사하지 않고(타입 선호도), 기본 설정에서 FK를 검사하지 않으며, 날짜 전용 타입이 없다.
