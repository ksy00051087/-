2-5JavaScript 'this' 정리


  • JavaScript의 함수는 호출될 때 this를 암묵적으로 전달 받음
  • JavaScript에서 this는 함수가 "호출되는 방식"에 따라 결정되는 현재 객체를 나타냄
  • 같은 함수라도 "누가 호출했는가"에 따라 this가 달라짐
  • 장점: 함수(메서드)를 하나만 만들어 여러 객체가 공유하여 각자 자신의 데이터로 동작하게 할 수 있음
  • 단점: 이런 유연함이 실수로 이어질 수 있다는 것


TIP — this가 헷갈릴 땐 '누가 점(.)을 찍어 호출했는가?'에 집중하세요. 점 앞의 객체가 this가 됩니다.


Python과 비교 — Python의 self는 "정의된 클래스의 인스턴스"로 고정되지만, JS의 this는 호출 시점에 결정됩니다. 화살표 함수만 예외로, 정의된 위치(상위 스코프)의 this를 그대로 씁니다.

3-1JSON — Key-Value 형태로 이루어진 자료 표기법


  • JavaScript의 Object와 유사한 구조를 가지고 있지만 JSON은 일정한 형식을 가진 "문자열"입니다.

  • 만약 참조 대상이 null 또는 undefined라면 에러가 발생하는 것 대신 평가를 멈추고 undefined를 반환



  
Optional chainingCtrl+Enter 실행
    

  

  
console 출력




장점


  • 참조가 누락될 가능성이 있는 경우 연결된 속성으로 접근할 때 더 짧고 간단한 표현식을 작성할 수 있음
  • 어떤 속성이 필요한지에 대한 보증이 확실하지 않는 경우에 객체의 내용을 보다 편리하게 탐색할 수 있음


주의사항


  1. 존재하지 않아도 괜찮은 대상에만 사용해야 함 (남용 X) — 왼쪽 평가대상이 없어도 괜찮은 경우에만 선택적으로 사용. 중첩 객체를 에러 없이 접근하는 것이 사용 목적이기 때문

// userData에 값을 할당하지 않은 문제가 있을 때 바로 알아낼 수 있어야 하기 때문

// Bad
userData?.address?.street
// Good
userData.address?.street
    2. 

  2. Optional chaining 앞의 변수는 반드시 선언되어 있어야 함

    console.log(myObj?.address) // Uncaught ReferenceError: myObj is not defined


정리


문법동작
obj?.propobj가 존재하면 obj.prop을 반환하고, 그렇지 않으면 undefined를 반환
obj?.[prop]obj가 존재하면 obj[prop]을 반환하고, 그렇지 않으면 undefined를 반환
obj?.method()obj가 존재하면 obj.method()를 호출하고, 그렇지 않으면 undefined를 반환


TIP — null과 undefined일 때만 동작합니다(0, '' 같은 falsy 값에는 멈추지 않음). 체인 중간이 null인 경우, 그 뒤의 코드는 실행되지 않습니다. 이를 '단락 평가'라고 부릅니다.

5-1배열 (Array) — 순서가 있는 데이터 집합을 저장하는 자료구조


  • 객체는 키(key)로 데이터를 관리하지만, 순서가 중요하지 않습니다.
  • '첫 번째', '두 번째'처럼 순서가 중요한 데이터 묶음이 필요할 때 사용하는 것이 바로 "순서가 있는 컬렉션, 배열(Array)"입니다.
  • 하지만 배열의 인덱스는 숫자로만 이루어져 있어, "키 자체가 데이터의 의미를 설명해주지 못하고", 특정 값을 찾기 위해서는 배열의 모든 요소를 "처음부터 순서대로 확인"해야 하는 단점이 있습니다.

  • length 속성을 사용해 배열에 담긴 요소 개수 확인 가능

6-1콜백 함수 (Callback function) — 함수의 인자로 전달되어, 특정 시점에 호출되는 함수


  • 어떤 작업이 완료된 후, "나중에 호출(Call back)해줘!"라고 넘겨주는 함수
  • 특정 작업(1초 기다리기, …)이 완료된 후, 시스템에 의해 나중에 호출(call back)되는 함수
  • ➤ "함수의 실행 권한"을 다른 함수에게 위임하는 것


콜백 함수 쉽게 이해하기 — 비유: 진동벨


  1. 카페에서 커피를 주문 (요청)
  2. 직원이 진동벨을 줌 (콜백 함수 전달) — "커피 다 되면(이벤트 발생 시), 이 벨을 울려주세요(함수 실행)."
  3. 우리는 자리에 앉아 다른 일을 진행
  4. 커피가 완성되면 직원이 진동벨을 울림 (콜백 함수 실행)

7-1순회: forEach — "배열의 모든 요소를 하나씩 훑으면서, 내가 전달한 함수를 실행해줘!"

8-1(심화) 집계: reduce — "배열의 요소를 하나씩 줄여가며(reduce), 결국 하나의 결과값으로 합쳐줘!"


  • 배열을 숫자 하나, 문자열 하나, 혹은 완전히 다른 형태의 객체나 배열로 변환할 때 사용
  • 핵심 비유 (눈덩이 굴리기) — 처음엔 작은 눈뭉치(초기값)였지만, 바닥을 구르며 눈(요소)을 계속 붙여서 거대한 눈사람(결과값)이 됨


arr.reduce((acc, cur, index, array) => {
  return nextAccValue
}, initialValue)


  1. acc (Accumulator, 누적값): 이전 단계까지 계산된 결과(눈덩이). return한 값이 다음 단계의 acc가 됨
  2. cur (Current, 현재값): 지금 처리 중인 배열의 요소 (새로 붙일 눈)
  3. initialValue (초기값): 눈덩이를 굴리기 시작할 때의 크기 (생략 가능하지만, 명시하는 것을 강력 권장)

8-5forEach의 중요성 — 왜 forEach가 중요할까


  • 우리는 이미 for...of를 배웠고, 기능적으로는 그것만 있어도 충분
  • 하지만, 모던 웹 개발(Vue, React)에서는 forEach와 같은 '배열 메서드' 방식을 훨씬 더 선호 — 곧 배우게 될 프론트엔드 프레임워크 Vue.js와 Axios(서버 통신)는 대부분이 이 구조로 되어 있음
  • 바로 '콜백 함수(Callback)' 구조 및 '코드의 작성 스타일' 때문


1. 선언형 프로그래밍 (Declarative)


  • for...of (명령형): "어떻게(How)" 순회할지 하나하나 명령 (인덱스, break 등 제어 중심)
  • forEach (선언형): "무엇을(What)" 할지만 신경 씀 (데이터 처리 중심)
  • 이점: 코드가 단순해지고, 데이터의 흐름이 명확히 보임. Vue나 React는 이러한 스타일을 지향. 즉, forEach는 단순 반복문이 아니라 프레임워크를 쓰기 위한 기초 체력


2. Vue와 Axios 미리보기 — 우리가 곧 배우게 될 기술들은 forEach와 똑같은 구조(메서드 + 콜백 함수)를 가짐


// 1. forEach 메서드
numbers.forEach((num) => {
  console.log(num)
})

// 2. map 메서드 (데이터 변형)
// Vue에서 데이터를 화면에 뿌릴 때 가장 많이 사용
const newNumbers = numbers.map((num) => {
  return num * 2
})

// 3. Vue에서 배우게 될 서버 통신 (Axios)
// forEach랑 구조가 동일
axios.get(url).then((response) => {
  console.log(response)
})

8-7클래스 (class) — 객체를 생성하기 위한 템플릿


  • 객체의 속성, 메서드를 정의하는 청사진 역할
  • '붕어빵'을 하나 만들 때마다 손으로 직접 모양을 빚는다고 상상해보세요. 100개를 만들려면 100번의 고된 수작업이 필요하겠죠? 객체를 하나씩 선언하는 것은 이와 같습니다. 만약 우리에게 '붕어빵 틀'이 있다면 어떨까요? 이 '붕어빵 틀'이 바로 "클래스(class)" 입니다.


클래스 기본 문법


  1. class 키워드 — 객체의 '설계도'인 클래스를 정의하기 위해 사용하는 예약어. 호이스팅 되지만, 선언 전에 접근하면 에러가 발생합니다. (TDZ)
  2. 클래스 이름 — 일반적으로 파스칼 케이스(PascalCase)로 작성. 함수처럼 이름을 생략한 '익명 클래스 표현식'으로 작성하는 것도 가능
  3. 생성자 메서드(constructor()) — new로 객체 생성 시 자동으로 호출되며, 속성 값의 초기 설정을 담당. 'constructor'라는 이름을 가진 메서드가 단 하나만 존재할 수 있음


호이스팅: 코드를 실행하기 전에 함수, 변수, 클래스 등의 선언이 스코프 맨 위로 끌어올려지는 것처럼 보이는 현상
TDZ (Temporal Dead Zone): let, const, class 선언 전, 접근을 막는 일시적 사각 지대


클래스 특징


  • ES6에서 도입
  • 생성자 함수를 사용하던 기존의 객체 생성 방식을 더 명확하고 객체 지향적으로 표현하기 위해 도입
  • 그래서 클래스는 내부적으로 생성자 함수를 기반으로 동작함


// 생성자 함수                         // 클래스
function Member(name, age) {           class Member {
  this.name = name                       constructor(name, age) {
  this.age = age                           this.name = name
  this.sayHi = function () {               this.age = age
    console.log(`Hi, I am ${this.name}`)  }
  }                                      sayHi() {
}                                          console.log(`Hi, I am ${this.name}`)
                                         }
                                       }


클래스 활용 · 'new' 연산자


  • new 키워드는 새 객체를 만들고, constructor를 호출하여 초기 속성 값을 설정
  • 메서드 안의 this는 메서드를 호출한 member1 자신을 가리킴
  • const instance = new ClassName(arg1, arg2) — 클래스나 생성자 함수를 사용하여 새로운 객체를 생성. 클래스의 constructor()는 new 연산자에 의해 자동으로 호출되며 특별한 절차 없이 객체를 초기화 할 수 있음
  • new 없이 클래스를 호출하면 TypeError 발생

Basic Syntax 02 확인문제


1. this 키워드에 대한 설명으로 올바른 것은?
  1. 항상 전역 객체(window)를 가리킨다.
  2. 함수가 선언될 때 가리키는 대상이 정해진다.
  3. 메서드를 호출한 객체를 가리킨다.
  4. 화살표 함수는 자신만의 this를 가진다.
정답: c) 메서드를 호출한 객체를 가리킨다. — this는 함수를 호출하는 방법에 따라 결정되며, 메서드 호출 시에는 해당 메서드를 호출한 객체를 가리킵니다.


2. 키와 값의 변수명이 같을 때 사용하는 문법은?
  1. 단축 속성
  2. 계산된 속성
  3. 구조 분해 할당
  4. 전개 구문
정답: a) 단축 속성 — 객체를 정의할 때, 키 이름과 값으로 쓰이는 변수 이름이 같다면 하나로 축약하여 사용할 수 있습니다.


3. 객체의 속성을 분해하여 변수에 할당하는 문법은?
  1. 단축 속성
  2. 계산된 속성
  3. 구조 분해 할당
  4. Optional Chaining
정답: c) 구조 분해 할당 — 객체의 속성을 여러 변수로 쉽게 추출할 수 있게 해주는 문법으로, 코드의 가독성을 높여줍니다.


4. 객체를 JSON 형식의 문자열로 변환하는 메서드는?
  1. JSON.parse()
  2. JSON.stringify()
  3. Object.toJSON()
  4. Object.toString()
정답: b) JSON.stringify() — JavaScript 값이나 객체를 JSON 문자열로 변환하는 역할을 합니다.


5. 배열의 가장 마지막에 요소를 추가하는 메서드는?
  1. pop()
  2. shift()
  3. unshift()
  4. push()
정답: d) push() — 배열의 끝에 하나 이상의 요소를 추가하고, 배열의 새로운 길이를 반환합니다.


6. 배열의 가장 앞에서 요소를 제거하는 메서드는?
  1. pop()
  2. shift()
  3. unshift()
  4. push()
정답: b) shift() — 배열에서 첫 번째 요소를 제거하고, 제거된 그 요소를 반환합니다.


7. 콜백 함수에 대한 설명으로 가장 적절한 것은?
  1. 함수가 자기 자신을 다시 호출하는 함수
  2. 다른 함수의 인자로 전달되는 함수
  3. 여러 개의 함수를 하나로 묶는 함수
  4. 반드시 비동기적으로 작동하는 함수
정답: b) 다른 함수의 인자로 전달되는 함수 — 다른 함수의 인자로 전달되어, 특정 작업이 끝난 후 외부 함수 내에서 호출되는 함수입니다. (a는 재귀 함수)


8. 배열의 각 요소에 대해 함수를 실행하지만, 아무것도 반환하지 않는 메서드는?
  1. map()
  2. filter()
  3. forEach()
  4. reduce()
정답: c) forEach() — 각 요소에 대해 주어진 함수를 실행하지만, 항상 undefined를 반환합니다.


9. 배열의 모든 요소에 함수를 적용한 결과로 새로운 배열을 만드는 메서드는?
  1. map()
  2. forEach()
  3. for...of
  4. Object.keys()
정답: a) map() — 배열의 모든 요소에 함수를 적용하고, 그 결과들을 모아 새로운 배열로 반환합니다.


10. 객체의 모든 키(key)를 배열로 반환하는 메서드는?
  1. Object.keys()
  2. Object.values()
  3. Object.entries()
  4. object.keys()
정답: a) Object.keys() — Object.keys(obj)는 주어진 객체가 가진 속성들의 이름(키)을 문자열 배열로 반환합니다. (d는 소문자 object라 존재하지 않음)


11. Optional Chaining (?.)을 사용하는 주된 목적은?
  1. 속성이 없으면 에러를 발생시키기 위해
  2. 중첩 객체의 속성을 에러 없이 안전하게 접근하기 위해
  3. 여러 함수를 연달아 호출하기 위해
  4. 중첩된 객체의 속성을 삭제하기 위해
정답: b) 중첩 객체의 속성을 에러 없이 안전하게 접근하기 위해 — 참조가 null 또는 undefined일 때 에러 대신 undefined를 반환하여 코드를 간결하게 만듭니다.


12. 클래스로부터 새로운 객체 인스턴스를 생성할 때 사용하는 키워드는?
  1. create
  2. instance
  3. new
  4. this
정답: c) new — new 연산자는 클래스의 생성자(constructor)를 호출하여 새로운 객체 인스턴스를 생성합니다.

객체 · 추가 객체 문법 · JSON


  • 객체는 키(key)와 값(value)으로 구성된 속성(property)들의 집합을 저장하는 자료형 · 점(.)이나 대괄호([])를 사용해 속성에 접근, 추가, 수정, 삭제 가능
  • 메서드는 객체의 속성에 할당된 함수 · this 키워드는 메서드를 호출한 객체
  • 일반 함수 안에서 this는 전역 객체(window)를 가리키지만, 화살표 함수는 자신만의 this를 갖지 않고 상위 스코프의 this를 참조 → 객체 메서드 내의 중첩된 함수에서 this를 다룰 때 화살표 함수가 유용함
  • 구조 분해 할당: { a, b } = obj · 전개 구문: { ...oldObj }(얕은 복사) · Optional Chaining: user.address?.street — 중간 속성이 null이나 undefined이면 에러 대신 undefined
  • JSON은 JS 객체와 구조는 유사하지만 전체가 하나의 문자열 · stringify(객체→JSON), parse(JSON→객체)






배열 · Array Helper Methods


  • 배열은 순서가 있는 데이터의 집합을 저장하는 자료구조
  • push()와 pop()은 배열의 끝에서, unshift()와 shift()는 배열의 앞에서 요소를 추가하거나 제거 — 모두 원본 배열을 직접 수정
  • Array Helper Methods: 배열을 순회하며 특정 작업을 수행하는 고차 함수들로, 콜백 함수를 인자로 받음
  • 콜백 함수: 다른 함수의 인자로 전달되어, 외부 함수 내에서 호출되는 함수
  • forEach(): 배열의 각 요소에 대해 콜백 함수를 실행함 반환 값은 없음
  • map(): 배열의 각 요소에 대해 콜백 함수를 실행하고, 그 결과를 모아 새로운 배열을 반환 · 원본 배열은 변경되지 않음






이 문서의 큰 줄기


  • 한 사람 = 객체, 여러 사람 = 배열, 모두에게 같은 작업 = 배열 헬퍼 메서드.
  • this는 점 앞의 객체. 콜백 안에서 바깥 this를 쓰려면 화살표 함수.
  • forEach는 반환값 없음(undefined) · map은 같은 길이의 새 배열 · filter는 같거나 짧은 새 배열 · 셋 다 원본은 그대로 / push·pop·shift·unshift는 원본을 바꾼다.
