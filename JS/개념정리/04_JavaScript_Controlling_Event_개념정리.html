1-2event — 웹 페이지 상에서 '무언가 일어났다는 신호 또는 사건'


JS 이벤트는 '영화 서비스'와 같습니다. 우리가 보고 싶은 영화 포스터에 마우스를 올리면(이벤트), 시스템은 마우스의 움직임을 감지(리스너)하고, 작은 미리보기 영상이나 설명을 보여주는(핸들러) 반응을 보입니다. 마우스 움직임 하나하나가 이벤트가 될 수 있고, 이러한 다양한 클릭, 입력, 변경하는 행위가 이벤트에 해당합니다.


DOM 요소와 이벤트


  • 모든 DOM 요소는 다양한 형태의 이벤트를 발생시킬 수 있음
  • 예) button 을 클릭하면 click 이벤트, input 값 변경 시 input 이벤트, …


DOM 요소: HTML 문서의 각 태그를 하나의 객체로 변환한 것






1-3event object — 이벤트에 관한 정보를 담은 객체


  • DOM에서 이벤트가 발생하면, 브라우저는 해당 이벤트에 관한 정보를 담은 'event object'를 자동으로 생성
  • 이벤트 종류: mouse(MouseEvent), input(InputEvent), keyboard(KeyboardEvent), … (MDN: Web APIs › Event)


TIP — 이벤트 객체는 이벤트 발생 순간의 상황(어떤 요소에서 이벤트가 발생했는지, 마우스 좌표는 어디인지, 눌린 키는 무엇인지 등)과 관련된 상세 정보를 담고 있습니다. 이를 통해 이벤트와 관련된 구체적인 정보를 참조할 수 있습니다.

1-4event handler — 특정 이벤트가 발생했을 때 실행되는 (콜백)함수


DOM 요소에서 event가 발생하면, 해당 event는 연결된 이벤트 처리기(event handler)에 의해 처리 됨.


이벤트 핸들러는 카페의 '바리스타'와 같습니다. 손님이 키오스크에서 아메리카노를 주문하면(이벤트), 바리스타는 정해 둔 레시피대로 커피를 만듭니다(핸들러 실행). 바리스타는 주문이 들어오기 전에는 커피를 만들지 않고 기다리다가, 주문이 들어온 순간에만 움직입니다. 이처럼 핸들러는 우리가 직접 호출하는 함수가 아니라, 이벤트가 발생했을 때 브라우저가 대신 호출해 주는 (콜백)함수입니다.


※ 보통 addEventListener를 통해 DOM 요소에 event handler를 등록합니다.






1-5.addEventListener() — 특정 DOM 요소에, 지정한 이벤트가 발생했을 때 실행할 이벤트 핸들러를 등록하는 메서드


addEventListener는 키오스크에 '주문 처리 규칙'을 등록하는 것과 같습니다. "아메리카노 버튼이 눌리면(click), 바리스타(handler)를 불러 주세요"라고 키오스크(리스너)에 미리 등록해 둡니다. 한 번만 등록해 두면, 이후 주문이 들어올 때마다 키오스크가 알아서 바리스타를 부릅니다. 등록할 때는 바리스타를 지금 부르는 것이 아니라 '누구를 부를지' 알려 주는 것이므로, handleClick()이 아닌 handleClick처럼 괄호 없이 함수를 전달합니다.


※ 이벤트 핸들러(콜백 함수)를 DOM 요소에 연결하는 역할을 담당합니다.


EventTarget.addEventListener(type, handler)
  DOM 요소          리스너           수신할 이벤트  핸들러


  • DOM 요소: HTML 문서의 각 태그를 하나의 객체로 변환한 것
  • 수신할 이벤트(type): 무언가 일어났다는 신호 또는 사건 — 수신할 이벤트 유형, 문자열로 작성 (ex. 'click', 'mouseover' 등)
  • 핸들러(handler): 특정 이벤트가 발생했을 때 실행되는 (콜백)함수 — 이벤트 발생 시 호출되는 콜백 함수 · 자동으로 event 객체를 첫번째 매개변수로 받음 · 반환 값 없음


element.addEventListener('click', function (event) {
  // 이벤트 처리 로직
})

2-2버블링 (Bubbling)


  • 한 요소에 이벤트가 발생하면, 해당 요소의 핸들러가 동작한 후 이어서 부모 요소의 핸들러가 동작하는 현상
  • 가장 최상단의 조상 요소(document, 그리고 window)를 만날 때까지 이 과정이 반복되면서 요소 각각에 할당된 핸들러가 동작
  • ➤ 최하위의 <p> 요소를 클릭하면 p → div → form 순서로 3개의 이벤트 핸들러가 모두 순차적으로 동작했던 것


TIP — 이벤트가 제일 깊은 곳에 있는 요소에서 시작해 부모 요소를 거슬러 올라가며 발생하는 것이 마치 물속 거품과 닮았기 때문에 버블링이라고 합니다.

Capturing phase → Target phase → Bubbling phase

  




3-1캡처링 (capturing)


  • 이벤트가 최상위 조상에서 타겟 요소까지 하위로 전파되는 단계 (버블링과 반대)
  • table 의 하위 요소 td를 클릭하면, 이벤트는 먼저 최상위 요소부터 아래로 전파됨 (캡처링)
  • 실제 이벤트가 발생한 지점(event.target)에서 실행된 후 다시 위로 전파 (버블링)


Window→Document→<html>→<body>→<table>→<tbody>→<tr>→<td> (Target)


① Capture Phase (위→아래) → ② Target Phase → ③ Bubbling Phase (아래→위)


TIP — 캡처링은 실제 개발자가 다루는 경우가 거의 없으므로 버블링을 집중해서 학습하는 것이 좋습니다.

버블링의 필요성
공통 조상에 핸들러 하나만 등록 (이벤트 위임)

  




4-1버블링이 필요한 이유


  • 만약 다음과 같이 각자 다른 동작을 수행하는 버튼이 여러 개가 있다고 가정하면, 각 버튼마다 서로 다른 이벤트 핸들러를 등록해야 할까?
  • ➤ 각 버튼의 공통 조상인 div 요소에 이벤트 핸들러 단 하나만 할당하기
  • 요소들의 공통 조상에 이벤트 핸들러를 하나만 등록하면, 여러 자식 요소에서 발생하는 이벤트를 한곳에서 효율적으로 다룰 수 있음
  • 공통 조상(div)에 할당한 핸들러에서 event.target을 이용하면 실제 어떤 버튼에서 이벤트가 발생했는지 알 수 있기 때문

Controlling Event 확인문제


1. 특정 이벤트가 발생했을 때 실행되는 함수는?
  1. 이벤트 리스너
  2. 이벤트 객체
  3. 이벤트 핸들러
  4. 이벤트 타입
정답: c) 이벤트 핸들러 — 이벤트 핸들러는 특정 이벤트 발생 시 호출되도록 작성된 콜백 함수입니다.


2. DOM 요소에 이벤트 핸들러를 등록하는 메서드는?
  1. setEvent()
  2. handleEvent()
  3. onEvent()
  4. addEventListener()
정답: d) addEventListener() — addEventListener()는 특정 DOM 요소에 지정된 타입의 이벤트를 처리할 함수(핸들러)를 등록합니다.


3. 한 요소의 이벤트가 부모 요소로 전파되는 현상은?
  1. 캡처링 (Capturing)
  2. 버블링 (Bubbling)
  3. 위임 (Delegation)
  4. 호이스팅 (Hoisting)
정답: b) 버블링 (Bubbling) — 이벤트가 가장 안쪽 요소에서 시작해 바깥쪽 부모 요소로 거슬러 올라가며 전파되는 현상입니다.


4. 이벤트 핸들러에 자동으로 전달되는 첫 번째 인자는?
  1. this
  2. event 객체
  3. target 요소
  4. currentTarget 요소
정답: b) event 객체 — 이벤트 발생 시, 해당 이벤트에 대한 상세 정보를 담은 event 객체가 핸들러에 자동으로 전달됩니다.


5. event.target이 가리키는 대상은?
  1. 이벤트가 처음 발생한 요소
  2. 이벤트 핸들러가 연결된 요소
  3. 부모 요소
  4. 최상위 document 객체
정답: a) 이벤트가 처음 발생한 요소 — event.target은 이벤트가 최초로 발생한 요소, 즉 이벤트의 실제 시작이 된 요소를 가리킵니다.


6. event.currentTarget이 가리키는 대상은?
  1. 이벤트가 처음 발생한 요소
  2. 이벤트 핸들러가 연결된 요소
  3. 자식 요소
  4. 최상위 window 객체
정답: b) 이벤트 핸들러가 연결된 요소 — event.currentTarget은 이벤트 리스너가 실제로 연결되어 있는 요소, 즉 this와 동일한 대상을 가리킵니다.


7. 요소의 기본 동작을 막는 메서드는?
  1. stopAction()
  2. cancelEvent()
  3. preventDefault()
  4. stopPropagation()
정답: c) preventDefault() — event.preventDefault()는 a 태그의 링크 이동이나 form의 제출과 같은 기본 동작을 취소합니다. (stopPropagation은 기본 동작이 아니라 전파(버블링)를 멈추는 메서드)


8. 버블링의 이점을 활용하는 주요 패턴은 무엇인가요?
  1. 여러 요소에 각각 핸들러 등록
  2. 상위 요소에 핸들러 하나만 등록
  3. 모든 요소에 preventDefault() 사용
  4. 캡처링 단계에서 이벤트 처리
정답: b) 상위 요소에 핸들러 하나만 등록 — 여러 하위 요소의 이벤트를 공통 상위 요소에서 한 번에 처리하여 효율성을 높일 수 있습니다.


9. 버블링과 캡처링의 차이를 올바르게 설명한 것은?
  1. 캡처링은 하향 전파, 버블링은 상향 전파
  2. 캡처링은 상향 전파, 버블링은 하향 전파
  3. 버블링은 기본 동작을, 캡처링은 전파를 막음
  4. 두 용어는 동일하며 실제 동작에 차이가 없음
정답: a) 캡처링은 하향 전파, 버블링은 상향 전파 — 캡처링은 부모에서 자식으로 하향식, 버블링은 자식에서 부모로 상향식으로 이벤트를 전달합니다.


10. event.target 과 event.currentTarget의 차이를 올바르게 설명한 것은?
  1. target은 리스너 부착 요소, currentTarget은 이벤트 발생 요소
  2. target은 이벤트 발생 요소, currentTarget은 리스너 부착 요소
  3. target은 항상 부모 요소, currentTarget은 항상 자식 요소
  4. 두 속성은 모든 상황에서 항상 동일한 요소를 가리킴
정답: b) target은 이벤트 발생 요소, currentTarget은 리스너 부착 요소 — target은 실제 이벤트 발생 요소를 의미하고, currentTarget은 리스너가 달린 요소(this와 동일한 대상)를 의미합니다.

이벤트 기본 개념


  • 이벤트(event): 웹 페이지에서 사용자의 클릭, 키보드 입력, 마우스 움직임 등 '무언가 일어났다는 신호 또는 사건'을 의미
  • 이벤트 객체(event object): 이벤트가 발생하면, 해당 이벤트에 대한 상세 정보(발생 위치, 마우스 좌표 등)를 담은 객체가 자동으로 생성
  • 이벤트 핸들러(event handler): 특정 이벤트가 발생했을 때 실행되도록 등록된 콜백 함수
  • addEventListener(type, handler): DOM 요소에 특정 이벤트(type)가 발생했을 때 실행할 이벤트 핸들러(handler)를 등록하는 메서드






이벤트 버블링 (Event Bubbling)


  • 한 요소에 이벤트가 발생하면, 그 요소의 핸들러가 동작한 후 부모 요소의 핸들러, 그 부모의 부모 핸들러 순으로 최상단까지 이벤트가 전파되는 현상
  • target vs currentTarget — 이벤트 객체 내에서 두 속성은 이벤트 전파 과정 중 요소를 참조하는 데 사용
    • event.target: 이벤트가 처음 발생한 가장 안쪽의 요소이며, 버블링이 진행돼도 이 값은 변하지 않음
    • event.currentTarget: 이벤트 핸들러가 연결된 현재 요소를 가리키고, 일반 함수 핸들러 내에서 this와 같은 값을 가짐
  • 버블링의 이런 특징을 이용하면 여러 자식 요소의 이벤트를 부모 요소 하나에서 관리할 수 있음






이 문서의 큰 줄기


  • 요소.addEventListener('이벤트', 핸들러) — 핸들러는 괄호 없이, 첫 인자로 event 객체가 자동 전달.
  • 이벤트는 캡처링(↓) → 타겟 → 버블링(↑). target은 실제 클릭한 곳, currentTarget(=this)은 핸들러가 붙은 곳.
  • 부모 하나에 핸들러를 달고 event.target으로 구분 = 버블링 활용 · 기본 동작이 방해되면 event.preventDefault() · 화살표 핸들러에서는 this 대신 event.currentTarget.
