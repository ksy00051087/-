1-1웹의 탄생과 JavaScript


  • 1990년 Tim Berners-Lee 경이 WWW, 하이퍼텍스트 시스템 고안하여 개발 — URL(특정 웹페이지나 파일을 찾기 위한 주소), HTTP(웹 브라우저와 서버가 데이터를 주고 받기 위한 통신 규약), WWW(전 세계적인 정보 공유 시스템)
  • 1994년 Netscape 사의 Netscape Navigator(NN) 브라우저 출시 — 당시 점유율 80% 이상 달성
  • 1995년 Netscape는 웹의 동적 기능을 만들기 위한 프로젝트를 시작 — Brendan Eich가 Mocha라는 이름의 스크립트 언어 개발
  • 이후 LiveScript로 이름을 변경 했으나 당시 가장 인기있던 'Java'의 명성에 편승하기 위해 JavaScript로 이름을 변경
  • JavaScript는 Netscape Navigator 2.0에 탑재되어 웹 페이지에 동적 기능을 추가하는 데 사용






1-21차 브라우저 전쟁과 파편화


  • 한편, Microsoft가 자체 웹 브라우저인 인터넷 익스플로러(IE) 출시 — JavaScript를 변형한 JScript를 개발하여 자체 브라우저에 탑재하기 시작
  • Microsoft는 IE를 자사 윈도우 운영체제에 내장하여 무료로 배포 → 빌 게이츠를 필두로 한 Microsoft의 공격적인 마케팅, 자금력 그리고 압도적인 윈도우 운영체제 점유율 앞에 Netscape는 점유율이 급격히 하락
  • 후날 Brendan Eich와 Netscape의 핵심 개발진은 모질라 재단을 설립(2003)하여 Firefox 브라우저를 출시함(2004)
  • 파편화: 브라우저마다 JavaScript 동작이 달라 개발자가 브라우저별 코드를 따로 작성해야 했음
웹 표준의 필요성
  • 어떤 브라우저나 기기에 상관없이 웹 사이트가 동일하게 작동하여, 일관된 사용자 경험을 제공합니다.
  • 브라우저별 코드를 따로 작성할 필요가 없어 개발 시간과 비용이 줄고, 유지보수가 쉬워집니다.






1-3ECMAScript의 탄생과 2차 브라우저 전쟁


  • JavaScript의 파편화를 막기 위해 Netscape사는 ECMA 재단(정보 통신 시스템을 위한 국제적 표준화 기구)에 웹 표준 제작을 요청
  • ECMA에서 ECMAScript라는 표준 언어를 정의하여 발표 (1997) — 이때부터 JavaScript는 ECMAScript 표준에 기반을 두고 발전하기 시작
  • 2차 브라우저 전쟁: IE의 독주에 Firefox가 대항하기 시작 → 2008년 Google의 Chrome 출시, 3년 만에 Firefox의 점유율을 넘어서고 시장을 장악
  • Chrome이 시장 우위를 점하게 된 이유 — 빠른 성능, 다양한 플랫폼 지원, 보안, Google 생태계 통합 등 다양한 이유가 있지만, 가장 결정적인 이유는 바로 "적극적인 웹 표준 준수"
  • 2차 브라우저 전쟁의 영향: Chrome이 웹 표준을 준수하고 새로운 웹 기술을 적극적으로 채택함으로써, 다른 브라우저 제조사들도 웹 표준 준수에 대한 중요성을 인식 → 웹을 문서에서 어플리케이션 플랫폼으로 바꾸는 데 결정적인 역할 (V8 자바스크립트 엔진)






1-4ECMAScript와 JavaScript


  • ECMAScript: Ecma International이 정의하고 있는 "표준화된 스크립트 프로그래밍 언어 명세" — 스크립트 언어가 준수해야 하는 규칙, 세부사항 등을 정의. 언어의 규칙 설명서로써 해당 언어의 문법·코드가 어떻게 동작해야 하는지를 정의하며, 기준이 되는 명세가 있기에 코드가 모든 환경에서 동일하게 동작하도록 보장합니다.
  • JavaScript: ECMAScript 표준을 구현한 구체적인 프로그래밍 언어. ECMAScript의 명세를 기반으로 하여 웹 브라우저나 Node.js와 같은 환경에서 실행됨
  • → ECMAScript는 JavaScript의 표준이며, JavaScript는 ECMAScript 표준을 따르는 구체적인 프로그래밍 언어
  • ECMAScript 5(ES5)에서 안정성과 생산성을 크게 높임(2009)
  • ECMAScript 2015(ES6)에서 객체지향 프로그래밍 언어로써 많은 발전을 이루어, 역사상 가장 중요한 버전으로 평가됨(2015)






1-5JavaScript의 현재


  • 현재는 Chrome, Firefox, Safari, Microsoft Edge 등 다양한 웹 브라우저가 경쟁하고 있으며, 모바일 등 시장이 다양화
  • 과거에는 JavaScript가 브라우저 내에서 웹 페이지의 동적인 기능을 구현하는 용도로만 사용되었음 — 예를 들어, 사용자의 입력에 따라 웹 페이지의 내용이 동적으로 변경되거나, 애니메이션 효과가 적용되는 등의 기능
  • 이후 Node.js(2009 출시)로 인해 브라우저 외부에서도 실행 가능해져 서버 사이드 개발에도 사용되기 시작함
  • 다양한 프레임워크와 라이브러리들이 개발되면서, 웹 개발 분야에서는 필수적인 언어로 자리 잡게 됨

2-2변수 작성 규칙 — 식별자(변수명)

  • 대소문자를 구분
  • 예약어 사용 불가 — 예약어: 프로그래밍 언어가 문법을 위해 미리 예약해둔 특별한 단어 (for, if, function 등)
  • 의미가 드러나는 이름을 사용하세요. 데이터의 의미를 설명하세요. (ex: userName, phoneNumber)
  • '$' 나 '_'로 시작하는 변수는 특별한 용도(DOM 선택, 라이브러리 변수)로 쓰이니, 일반 변수와 구분하세요.

DOM (Document Object Model)
브라우저에서의 JavaScript · DOM 정의 · DOM 특징 · document 객체 · DOM 트리

  




3-1웹 브라우저에서의 JavaScript


  • 웹 페이지에서 동적인 기능을 담당 (HTML은 구조, CSS는 스타일)
  • JavaScript 사용 방법 — 1. HTML 문서 내부 <script> 태그 2. js 확장자 파일 <script src="hello.js"></script> 3. HTML 태그의 inline 속성 (권장하지 않음)
  • 스크립트는 보통 <body> 끝(또는 defer)에 두어 HTML이 먼저 그려진 뒤 실행되게 합니다.
<!-- 1. 내부 -->
<body>
  <script>
    console.log('hello')
  </script>
</body>

<!-- 2. 외부 파일 -->
<script src="hello.js"></script>

<!-- 3. inline (비권장) -->
<button onclick="console.log('hi')">click</button>






3-2DOM이란?


  • 브라우저가 웹 페이지를 표현하기 위해 사용하는 데이터 구조 — HTML 문서 구조를 보면 우측 이미지와 같은 나무(트리) 모양을 가짐. 이 구조를 객체 모델(Document Object Model), 줄여서 DOM이라고 부름
  • 웹 페이지(Document)를 구조화된 객체로 제공하여 프로그래밍 언어가 페이지 구조에 접근할 수 있는 방법을 제공 — 문서 구조, 스타일, 내용 등을 변경할 수 있도록 함
  • 프로그래밍 언어가 웹 페이지에 접근 및 조작 할 수 있도록, 페이지 요소들을 객체 형태로 제공하며 이에 따른 메서드 또한 제공
  • DOM은 문서를 부모-자식 관계의 계층 구조로 표현하며, DOM 조작은 웹페이지에 실시간으로 변화를 주고, 사용자의 클릭이나 키보드 입력같은 이벤트에 반응하는 동적인 페이지를 만드는 기반이 됩니다.






3-3document 객체와 DOM 트리


  • document 객체: 웹 페이지를 나타내는 DOM 트리의 최상위 객체 — HTML 문서의 모든 콘텐츠에 접근하고 조작할 수 있는 진입점
  • DOM에서 모든 요소, 속성, 텍스트는 하나의 객체 — 모두 document 객체의 하위 객체로 구성됨
  • HTML 태그를 나타내는 elements의 node는 문서의 구조를 결정 — 이들은 다시 자식 node를 가질 수 있음 (ex. document.body)
  • 예: 개발자 도구 콘솔에서 document.title = 'Hello :)' 를 입력하면 탭 제목이 바뀜

5-1클래스 속성 조작 — classList


  • element.classList: 요소의 클래스 목록을 DOMTokenList(유사 배열) 형태로 반환 — HTML 요소의 클래스 목록을 쉽게 제어(추가/제거)하는 도구

6-1Node · NodeList · Element


  • Node: DOM의 기본 구성 단위 — DOM 트리의 각 부분은 Node라는 객체로 표현됨. Document Node ⇒ HTML 문서 전체를 나타내는 노드 / Element Node ⇒ HTML 요소를 나타내는 노드 (예를 들어 <p>) / Text Node ⇒ HTML 텍스트 (Element Node 내의 텍스트 컨텐츠를 나타냄) / Attribute Node ⇒ HTML 요소의 속성을 나타내는 노드
  • NodeList: DOM 메서드를 사용해 선택한 Node의 목록 — 배열과 유사한 구조를 가짐. Index로만 각 항목에 접근 가능. JavaScript의 배열 메서드 forEach 사용 가능. querySelectorAll()에 의해 반환되는 NodeList는 DOM의 변경사항을 실시간으로 반영하지 않음 (정적) — DOM이 나중에 변경되더라도 이전에 이미 선택한 NodeList 값은 변하지 않음
  • Element: Node의 하위 유형 — DOM 트리에서 HTML 요소를 나타내는 특별한 유형의 Node. 예를 들어, <p>, <div>, <span>, <body> 등의 HTML 태그들이 Element 노드를 생성. Node의 속성과 메서드를 모두 가지고 있으며 추가적으로 요소 특화된 기능(예: className, innerHTML, id 등)을 가지고 있음 → 모든 Element는 Node이지만, 모든 Node가 Element인 것은 아님
  • Parsing: 브라우저가 문자열을 해석하여 DOM Tree로 만드는 과정

6-3변수 선언 키워드 — var


  • ES6 이전에 변수 선언에 사용했던 키워드
  • 재할당 가능 & 재선언 가능
  • 함수 스코프(function scope)를 가짐 — 블록 안에서 선언해도 함수 전체(또는 전역)에서 접근 가능 → 블록 밖에서도 전역 변수처럼 동작하므로 절대 사용하지 않음

  • 변수 선언 시 var, const, let 키워드 중 하나를 사용하지 않으면 자동으로 var로 선언됨 (전역)
  • 함수 스코프: 함수 내부에서 선언된 변수는 함수 바깥에서 접근 불가

6-4호이스팅 (Hoisting)


  • 변수를 선언 이전에 참조할 수 있는 현상 — 변수 선언이 코드의 최상단으로 끌어올려지는 것처럼 동작
  • JavaScript 엔진은 코드를 실행하기 전에 선언문을 먼저 처리 — 모든 변수는 선언(Declaration) → 초기화(Initialization) → 할당(Assignment) 단계로 생성. 다만, '초기화'가 함께 이루어지느냐에 따라 동작이 달라짐
varlet · const
동작스코프 최상단에서 선언과 동시에 undefined로 초기화됨스코프 최상단으로 선언(이름 등록)은 되지만, 실제 코드 라인에 도달하기 전까지 초기화(메모리 할당)는 되지 않음
결과변수 선언 문장 이전에 접근해도 에러가 나지 않고 undefined를 반환초기화되지 않은 상태에서 접근하려 하므로 참조 에러(ReferenceError)가 발생
함수 선언식선언, 할당(함수 본체)이 모두 동시에 최상단으로 끌어올려지므로, 선언 전에도 함수를 문제없이 호출할 수 있음함수 표현식은 변수(let, const) 규칙을 따름
일시적 사각지대 (TDZ, Temporal Dead Zone)
  • 스코프의 시작 지점부터 변수의 초기화가 이루어지는 지점(실제 코드 선언부)까지의 구간
  • let, const, class는 호이스팅이 되지만 이 TDZ에 갇혀 있기 때문에, 선언 전에 접근할 수 없습니다.
  • 만약 호이스팅이 아예 되지 않았다면 "age is not defined"(정의되지 않음) 에러가 떠야 하지만, 엔진이 변수의 존재는 알고 있기 때문에 initialization 관련 에러("Cannot access 'age' before initialization")가 발생
  • 이는 개발자의 실수를 방지하는 안전장치 역할을 합니다.

JavaScript DOM 확인문제


1. JavaScript의 파편화를 막기 위해 ECMA 재단에서 만든 표준 언어는?
정답: ECMAScript
2. 다음 중 예약어로 변수명으로 쓸 수 없는 것은?
  1. userName
  2. function
  3. $el
  4. _count
정답: function — 함수 선언 키워드로, 프로그래밍 언어가 예약해둔 단어이므로 변수명으로 쓸 수 없습니다.
3. 변수 선언 시 기본으로 권장되는 키워드는?
  1. var
  2. let
  3. const
  4. 없음
정답: const — const를 기본으로 사용하여 의도치 않은 재할당을 막고, 필요시에만 let을 사용합니다.
4. DOM이란?
정답: 웹 페이지를 구조화된 객체로 제공하는 API — DOM(Document Object Model)은 프로그래밍 언어가 페이지 구조에 접근할 수 있게 합니다.
5. CSS 선택자와 일치하는 첫 번째 요소를 반환하는 메서드는?
정답: querySelector()
6. CSS 선택자와 일치하는 모든 요소를 NodeList로 반환하는 메서드는?
정답: querySelectorAll()
7. 요소에 클래스를 추가하는 classList의 메서드는?
정답: add() — add()를 사용하여 지정한 클래스 값을 추가할 수 있습니다.
8. 요소의 속성 값을 설정하는 메서드는?
정답: setAttribute() — 지정된 요소의 속성 값을 설정하거나 갱신합니다.
9. HTML 태그를 제외한 순수한 텍스트 데이터만 가져오거나 설정하는 속성은?
정답: textContent
10. 새로운 HTML 요소를 메모리에 생성하는 메서드는?
정답: createElement() — 메모리에만 생성되므로 문서에 삽입해야 보입니다.
11. 한 노드를 특정 부모 노드의 자식 목록 중 마지막 자식으로 삽입하는 메서드는?
정답: appendChild()
12. 함수 스코프를 가지며 사용을 권장하지 않는 변수 선언 키워드는?
정답: var — 블록 스코프를 가지는 let과 const가 권장됩니다.
