학습 시작 — 웹사이트에 생기 불어넣기

Onboarding · 학습 목표

"내가 만든 웹 페이지, 왜 이렇게 밋밋할까? 내 웹사이트에 생기를 불어넣고 싶다면?"

  • 우리가 매일 방문하는 웹사이트들은 화려한 이미지, 로고, 그리고 아름다운 디자인으로 가득합니다.
  • 또한, 사용자들은 자신의 프로필 사진을 직접 올리고 변경하기도 합니다.
  • 지금까지 우리가 만든 Django 페이지에는 CSS도, 이미지도, 사용자가 올린 파일도 없었죠. 과연 이런 요소들은 어떻게 웹 페이지에 적용되는 걸까요?
  1. 이번 시간 학습을 마치면, 직접 만든 웹 페이지에 로고 이미지를 넣고, CSS로 디자인을 꾸미며, 사용자가 직접 이미지를 업로드하는 게시판을 만들 수 있게 됩니다.
  2. 웹 개발의 핵심인 정적 파일(Static files)과 미디어 파일(Media files)을 다루며 여러분의 웹사이트를 한층 더 다채롭게 만들게 될 것입니다.
학습 목표
  • Django에서 정적 파일의 역할과 처리 과정을 이해하고 적용할 수 있다.
  • 사용자가 업로드한 미디어 파일을 저장하고 관리할 수 있다.
  • ImageField와 ModelForm을 활용하여 이미지 업로드 기능을 구현할 수 있다.
1

Static files

정적 파일 · 웹 서버와 정적 파일 · URL의 필요성 · 처리 과정

1-1Static files란?

정적 파일 — 서버 측에서 변경되지 않고 고정적으로 제공되는 파일 (이미지, JS, CSS 파일 등).

마치 식당에 비치된 '인쇄된 메뉴판'과 같습니다. 메뉴판은 손님이 바뀐다고 해서 내용이 바뀌지 않고, 항상 동일한 모습으로 제공됩니다.

1-2웹 서버와 정적 파일

  • 웹 서버의 기본 동작은 "특정 위치(URL)에 있는 자원(Resource)을 요청(HTTP request) 받아서 응답(HTTP response)을 처리하고 제공하는 것"
  • 마치 도서관 사서에게 "A-3 구역의 3번째 책을 주세요"라고 요청하면, 사서가 책을 찾아 우리에게 건네주는 것과 같음
  • 여기서 'A-3 구역의 3번째'가 바로 URL이고, '책'이 자원(Resource)에 해당

1-3정적 파일과 URL의 관계

  • 웹 서버가 제공하는 가장 기본적인 자원이 바로 정적 파일(Static Files)
  • 정적 파일 제공 — 웹 서버는 요청 받은 URL을 보고, 서버 컴퓨터의 특정 폴더에 저장된 CSS, JS, 이미지 같은 정적 파일을 찾아 응답
  • URL의 필요성 — 결국 "정적 파일이 사용자에게 보이려면, 그 파일에 접근할 수 있는 고유한 주소(URL)가 반드시 필요하다"

1-4처리 과정 요약

  1. 사용자: 브라우저에 http://example.com/images/logo.png라는 주소를 입력하며 이미지를 요청
  2. 웹 서버: /images/logo.png라는 URL을 확인하고, 서버에 미리 약속된 폴더에서 logo.png 파일을 찾음
  3. 웹 서버: 찾은 이미지 파일을 HTTP 응답에 담아 사용자에게 전송
  4. 사용자: 브라우저가 응답 받은 이미지 파일을 화면에 보여줌

Static files 기본 경로 · 추가 경로

app/static/ · load 태그 · static 태그 · STATIC_URL · STATICFILES_DIRS

2-1Static files 기본 경로

정적 파일이 위치해야 하는 기본 경로: app폴더/static/

기본 경로 CSS 스타일 제공하기
  1. articles/static/stylesheets/ 경로에 CSS 파일 배치하기
  2. 메인 페이지에서 CSS 파일 불러오기
  3. CSS가 적용된 것을 확인 (개발자 도구: static tag가 만들어 낸 주소는 /static/으로 시작)
/* articles/static/stylesheets/style.css */
h1 {
  color: crimson;
}
<!-- articles/index.html -->
{% load static %}
<!DOCTYPE html>
<html lang="en">
<head>
  <link rel="stylesheet" href="{% static 'stylesheets/style.css' %}">
</head>
<body>
  <h1>Articles</h1>
</body>
</html>
<!-- 렌더링 결과: <link rel="stylesheet" href="/static/stylesheets/style.css"> -->
  • static files 경로는 DTL의 static tag를 사용해야 함
  • built-in tag가 아니기 때문에 load tag를 사용해 import 후 사용 가능
  • 경로는 app/static/ 이후 경로부터 작성

2-2'load' tag

특정 라이브러리의 태그와 필터를 현재 템플릿에서 사용할 수 있도록 불러오는 역할.

  • {% load static %}은 {% static %} 태그를 사용하기 위해, Django 템플릿 시스템에 "이제부터 static 관련 태그를 사용하겠다."고 알려주는 선언문
  • load 태그는 템플릿 파일의 가장 상단에 한 번만 작성하면 됩니다
{% extends %}를 사용하는 템플릿에서는 extends가 첫 줄이고 load는 그 아래에 씁니다. 또한 부모 템플릿에서 load 했더라도 자식 템플릿에서 다시 load 해야 합니다.

2-3'static' tag · STATIC_URL

{% static '경로' %}
  • settings.py 파일의 STATIC_URL 값을 앞에 붙여 정적 파일의 웹 주소(/static/css/style.css)를 만들어 줌
  • 예: STATIC_URL = 'static/'이고 CSS 파일이 static/css/style.css에 위치한다면, 필요한 위치에 {% static 'css/style.css' %}로 작성

STATIC_URL — 웹 페이지에서 정적 파일에 접근할 때 사용할 URL의 시작 부분(접두사)을 지정하는 설정. 이는 서버 컴퓨터에 저장된 실제 파일 경로가 아니라, 오직 웹(브라우저)에서만 사용되는 주소입니다. 마치 서버의 정적 파일 폴더에 '/static/'이라는 웹 주소 별명을 붙여주는 것과 같습니다. 브라우저가 이 별명으로 파일을 요청하면, Django는 약속된 실제 폴더에서 파일을 찾아 응답합니다.

# settings.py
STATIC_URL = 'static/'     # 기본값

2-4기본 경로 이미지 파일 제공하기

<!-- articles/static/images/sample-1.png 배치 후 -->
{% load static %}
<img src="{% static 'images/sample-1.png' %}" alt="sample image">

제공된 이미지의 URL 확인: http://127.0.0.1:8000/static/images/sample-1.png

Static file URL이 만들어지기까지 — 기본 주소 + STATIC_URL + 정적 파일 경로 = http://127.0.0.1:8000/ + static/ + images/sample-1.png

2-5Static files 추가 경로 — STATICFILES_DIRS

STATICFILES_DIRS — 정적 파일의 기본 경로 외에 추가 경로 목록(리스트)을 정의하는 설정. 마치 기본 도서관 외에, 책을 보관하는 '외부 창고'들의 주소 목록을 알려주는 것과 같습니다. Django는 이 목록에 있는 모든 창고를 방문하여 필요한 정적 파일을 찾습니다.

이 설정은 여러 앱에서 공통으로 사용되는 CSS 프레임워크나 JavaScript 라이브러리처럼 특정 앱에 속하지 않는 정적 파일들을 프로젝트 최상위 폴더(BASE_DIR) 같은 곳에 두고 싶을 때 매우 유용합니다.

# settings.py
STATICFILES_DIRS = [
    BASE_DIR / 'static',
]

이처럼 설정하면, Django는 각 앱의 static/ 폴더뿐만 아니라 프로젝트 최상위의 static/ 폴더도 정적 파일을 찾는 경로로 사용하게 됩니다. → Django: STATICFILES_DIRS를 먼저, 그 다음 각 앱의 static/ 폴더를 찾음.

<!-- 프로젝트 최상위 static/sample-2.png 배치 후 -->
<img src="{% static 'sample-2.png' %}" alt="sample image">
<!-- http://127.0.0.1:8000/static/sample-2.png -->

2-6정적 파일을 제공하려면 요청에 응답하기 위한 URL이 필요

서버 컴퓨터에 파일이 존재하는 것만으로는 웹 페이지에 보일 수 없음. 웹의 손님(브라우저)이 파일을 찾아올 수 있도록 반드시 '웹 주소(URL)'라는 문패를 달아줘야 합니다.

구분무엇비유
서버 (내 컴퓨터)실제 파일 경로"내 방 책상 위 세 번째 서랍"
웹 (인터넷 세상)URL (웹 주소)"서울시 강남구 테헤란로 999"

Media files · 이미지 업로드

미디어 파일 · ImageField · MEDIA_ROOT · MEDIA_URL · 업로드 구현 8단계

3-1Media files

미디어 파일 — 사용자가 웹사이트를 통해 직접 업로드하는 파일 (이미지, PDF, 동영상 등). 마치 쇼핑몰의 로고·배너는 정적 파일이지만, 고객이 올린 상품 후기 사진은 미디어 파일인 것과 같습니다.

3-2ImageField()

  • 이미지 파일을 업로드하기 위해 사용하는 Django 모델 필드
  • 데이터베이스 저장 방식 — 가장 중요한 특징은 이미지 파일 자체가 데이터베이스에 저장되는 것이 아니라는 것
  • 데이터베이스에는 MEDIA_ROOT 기준 상대 경로(예: images/sample.png)만 저장되고, 실제 파일은 서버의 지정된 폴더(MEDIA_ROOT)에 저장
class Article(models.Model):
    # 이미지는 'MEDIA_ROOT/images/' 경로에 저장되고,
    # DB에는 'images/sample.png'와 같은 경로 문자열이 저장됨
    image = models.ImageField(upload_to='images/')

upload_to는 선택 인자입니다.

3-3미디어 파일을 제공하기 전 준비사항

  1. settings.py에 MEDIA_ROOT, MEDIA_URL 설정
  2. 작성한 MEDIA_ROOT와 MEDIA_URL에 대한 URL 지정

MEDIA_ROOT — 미디어 파일의 '실제 창고' 주소. 사용자가 업로드한 미디어 파일들이 서버 컴퓨터 어디에 저장될지를 지정하는 절대 경로. 서버 내부에서만 사용하는 물리적인 폴더 주소로, Django는 파일을 저장하거나 읽어올 때 이 경로를 사용합니다.

MEDIA_URL — 미디어 파일의 '웹 주소 별명'. MEDIA_ROOT에 저장된 파일들을 웹 페이지에서 접근할 때 사용할 URL 시작 부분을 지정. STATIC_URL과 동일한 역할로, 실제 저장 위치를 숨기고 웹에서 사용할 공개 주소를 만듭니다.

# settings.py
# 프로젝트 폴더(BASE_DIR) 안에 'media'라는 폴더를 실제 저장소로 사용
MEDIA_ROOT = BASE_DIR / 'media'
# media/ 라는 주소로 파일을 요청하면 MEDIA_ROOT 폴더에서 찾아 응답
MEDIA_URL = 'media/'

3-4MEDIA_ROOT와 MEDIA_URL에 대한 URL 지정

# crud/urls.py
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    path('admin/', admin.site.urls),
    path('articles/', include('articles.urls')),
] + static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
  • settings.MEDIA_URL: "media/로 시작하는 URL 요청이 오면,"
  • document_root=settings.MEDIA_ROOT: "MEDIA_ROOT에 지정된 실제 폴더에서 파일을 찾아서 보여줘라"
Django 개발 서버는 정적 파일(static)은 자동으로 제공하지만, 사용자가 올린 미디어 파일은 자동으로 제공하지 않습니다. 그래서 "media/로 요청이 오면 MEDIA_ROOT 폴더에서 찾아라"라는 규칙을 직접 추가해야 합니다. 이 static() 설정은 개발 단계(DEBUG=True)에서만 동작합니다. 실제 서비스에서는 웹 서버나 별도 저장소가 파일을 제공합니다(→ 참고: AWS 인프라 이해하기).

3-5이미지 업로드 구현 (1/8 ~ 3/8) — 모델과 Pillow

# articles/models.py
class Article(models.Model):
    title = models.CharField(max_length=10)
    content = models.TextField()
    image = models.ImageField(blank=True)          # ← 추가
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
  • blank=True 속성을 작성해 폼에서 이미지를 비워도 유효성 검사를 통과하도록 설정 → 게시글 작성 시 이미지 첨부 없이도 작성할 수 있도록 하기 위함 (blank: 폼 유효성 검사 시 해당 필드를 필수 또는 선택 사항으로 만들지 결정하는 속성)
  • 기존 필드 사이에 작성해도 실제 테이블 생성 시에는 가장 우측(뒤)에 추가됩니다

Pillow — 파이썬에서 이미지를 열고, 크기 조절이나 필터 적용 같은 다양한 편집 작업을 수행한 후 저장할 수 있게 해주는 필수 이미지 처리 라이브러리. ImageField를 사용하려면 반드시 Pillow 라이브러리가 필요합니다.

3-6이미지 업로드 구현 (4/8) — enctype

<!-- articles/create.html -->
<form action="{% url 'articles:create' %}" method="POST"
      enctype="multipart/form-data">
  {% csrf_token %}
  {{ form.as_p }}
  <input type="submit">
</form>

enctype 속성 — form 데이터가 서버로 제출될 때 해당 데이터가 어떤 형식으로 인코딩될지 지정하는 속성.

파일 업로드 시에는 반드시 multipart/form-data로 설정해야 합니다.

https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form

3-7이미지 업로드 구현 (5/8) — request.FILES

# articles/views.py
def create(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST, request.FILES)
        if form.is_valid():
            article = form.save()
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm()
    context = {'form': form}
    return render(request, 'articles/create.html', context)
ModelForm의 2번째 인자로 요청 받은 파일 데이터를 작성하는 이유? — ModelForm의 상위 클래스인 BaseModelForm의 생성자 함수의 2번째 위치 인자로 파일(files)을 받도록 설정되어 있습니다.

3-8이미지 업로드 구현 (6/8 ~ 8/8) — 확인

  1. 게시글 작성 페이지에서 새로 추가된 input 태그 확인: Image: [파일 선택] (form 태그에 enctype="multipart/form-data")
  2. 이미지 업로드 후 이미지 파일 위치 확인: MEDIA_ROOT 경로(media/)에 업로드된 이미지 파일 (media/images/sample-1.png)
  3. 이미지 업로드 후 DB 확인: 이미지 파일 자체가 데이터베이스에 저장되는 것이 아닌 upload_to 경로를 기준으로 파일 경로(문자열)만 저장 (예: image 컬럼 = images/sample-1.png)
Tip — 이 방식은 데이터베이스의 크기를 작게 유지하고 성능을 높이는 데 매우 효과적입니다.

4-1게시글 상세 페이지에 업로드한 이미지 제공하기

.url 속성 — 업로드 파일의 웹 주소. ImageField나 FileField에 저장된 파일 객체에서 .url 속성을 사용하면, 해당 파일을 웹에서 접근할 수 있는 전체 URL 주소를 얻을 수 있습니다.

<!-- articles/detail.html -->
{% if article.image %}
  <img src="{{ article.image.url }}" alt="img">
{% endif %}

업로드 이미지 출력 확인 및 URL: http://127.0.0.1:8000/media/images/sample-1.png

이미지를 업로드하지 않은 게시물에서 article.image.url을 사용하면 연결된 파일이 없다는 에러(ValueError)가 발생합니다. 이미지 데이터가 있는 경우만 이미지를 출력할 수 있도록 if 태그를 활용합니다.

# articles/views.py : update view에서 업로드 파일에 대한 추가 코드 작성
def update(request, pk):
    article = Article.objects.get(pk=pk)
    if request.method == 'POST':
        form = ArticleForm(request.POST, request.FILES, instance=article)
        if form.is_valid():
            form.save()
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm(instance=article)
    context = {'article': article, 'form': form}
    return render(request, 'articles/update.html', context)

5-1'upload_to' argument

1) 날짜를 이용한 경로 구성

strftime()의 형식 코드를 사용하여 파일이 업로드된 날짜를 기준으로 폴더를 자동으로 생성합니다. (%Y: 4자리 연도, %m: 월, %d: 일)

class Article(models.Model):
    # 2100년 1월 1일에 업로드하면 '2100/01/01/' 폴더에 저장됨
    image = models.ImageField(blank=True, upload_to='%Y/%m/%d/')
2) 함수를 이용한 동적 경로 생성

더 복잡한 로직으로 경로를 만들고 싶을 때는, upload_to에 함수를 직접 전달할 수 있습니다. (instance: 현재 저장되는 모델 인스턴스, filename: 업로드된 파일의 원본 이름)

# 경로 생성 함수 정의
def articles_image_path(instance, filename):
    # instance.user.username을 통해 게시글 작성자의 이름을 가져옴
    # 예: 'images/ssafy_user/my_photo.jpg' 와 같은 경로를 반환
    return f'images/{instance.user.username}/{filename}'

class Article(models.Model):
    image = models.ImageField(blank=True, upload_to=articles_image_path)

user 필드는 이후 Authentication 수업에서 학습합니다.

5-2AWS 인프라 이해하기

AWS (Amazon Web Services) — 아마존이 제공하는 클라우드 컴퓨팅 플랫폼. 서버, 스토리지, 데이터베이스 같은 IT 인프라를 직접 구매하지 않고, 인터넷을 통해 빌려 쓰는 서비스입니다.

서비스역할설명
EC2가상 서버클라우드에 생성하는 고성능 컴퓨터. 웹 애플리케이션(Django)이 실행되는 컴퓨터의 역할
S3파일 저장소이미지, 동영상 등 모든 파일을 보관하는 객체 스토리지. 사용자가 올린 이미지(미디어 파일)나 사이트의 로고·CSS(정적 파일)를 보관하는 창고
RDS데이터베이스데이터를 체계적으로 관리하는 관계형 데이터베이스. 회원 정보, 게시글 등 중요한 데이터를 기록하고 관리하는 장부
데이터 흐름도 요약
  1. 사용자 → EC2 (HTTP Request): 사용자가 브라우저를 통해 웹사이트에 접속(요청). 이 요청은 가장 먼저 EC2에 도착
  2. EC2 ↔ RDS (DB Query): EC2의 Django 애플리케이션은 요청을 처리하기 위해 필요한 데이터(예: 게시글, 사용자 정보)를 RDS에서 조회하거나 새로운 데이터를 저장
  3. EC2 → 사용자 (HTML Response): EC2는 데이터베이스에서 가져온 정보와 HTML 템플릿을 조합하여 완전한 웹 페이지(HTML)를 만들어 사용자에게 응답. 이 HTML 안에는 이미지, CSS, JS 파일의 주소가 S3를 가리키도록(src="https://...") 포함되어 있음
  4. 사용자 → S3 (File Request): HTML을 받은 브라우저는 페이지를 완전하게 그리기 위해, HTML에 명시된 S3 주소로 직접 이미지나 CSS 파일을 요청 (EC2를 거치지 않음)
  5. S3 → 사용자 (File Response): S3는 요청 받은 파일을 사용자 브라우저에 직접 전송
  6. (파일 업로드 시) 사용자 → EC2 → S3: 사용자가 이미지를 업로드하면, 요청은 EC2로 감. EC2의 Django 앱은 파일을 받아 S3에 저장

AWS 장점 — 확장성(필요에 따라 서버 사양이나 저장 공간 등을 몇 번의 클릭만으로 자유롭게 조절), 글로벌 서비스(전 세계에 위치한 데이터 센터를 통해 어떤 국가의 사용자에게도 빠르고 안정적인 서비스 제공).
