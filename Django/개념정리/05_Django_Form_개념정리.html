학습 시작 — 데이터를 직접 검증하지 않아도 된다

Onboarding · 학습 목표

"웹사이트에서 회원가입이나 글을 쓸 때, 우리는 직접 데이터가 제대로 입력됐는지 일일이 확인하지 않아도 됩니다!"

  1. Django가 제공하는 Form을 통해 입력 데이터가 정확한지 확인합니다.
  2. 입력된 정보를 자동으로 ModelForm 클래스의 save() 메서드를 통해 데이터베이스에 저장하고, 사용자에게 결과를 응답합니다.
  3. 사용자가 잘못된 정보를 입력하면 Django의 Form 클래스가 제공하는 is_valid() 메서드를 통해 자동으로 오류 메시지를 전달해줍니다.

이번 시간이 끝나면, Django의 Form 및 ModelForm 클래스를 통해 복잡한 유효성 검사 로직을 작성하지 않고도 웹페이지가 정확하게 데이터를 처리하도록 만들 수 있습니다.

학습 목표
  • Django Form이 무엇인지 설명할 수 있다.
  • Form 클래스를 정의하고 유효성 검사를 직접 구현할 수 있다.
  • ModelForm을 활용하여 데이터베이스와 연동되는 입력 폼을 생성할 수 있다.
  • HTTP 요청 방식(GET/POST)에 따라 view 함수의 구조를 통합할 수 있다.

Django Form

HTML form의 한계 · 유효성 검사 · Form class 정의 · new 로직 적용 · Widgets

1-1HTML 'form'의 한계와 유효성 검사

지금까지 사용자로부터 데이터를 제출받기 위해 HTML form을 사용했습니다. 그러나 비정상적 혹은 악의적인 요청을 필터링할 수 없음. 유효한 데이터인지에 대한 확인이 필요합니다.

유효성 검사란? — 수집한 데이터가 정확하고 유효한지 확인하는 과정. 유효성 검사를 구현하기 위해서는 입력 값, 형식, 중복, 범위, 보안 등 많은 것들을 고려해야 함. 이런 과정과 기능을 직접 개발하는 것이 아닌 Django가 제공하는 Form을 사용합니다.

Django Form — 사용자 입력 데이터를 수집하고, 처리 및 유효성 검사를 수행하기 위한 도구. 유효성 검사를 단순화하고 자동화할 수 있는 기능을 제공하며, 개발자는 이를 통해 빠르고 일관된 입력 검증 기능을 구현할 수 있습니다.

사용자가 잘못 입력한 데이터는 자동으로 오류로 처리되어 안전성을 높입니다.

1-2Form Class 정의

Form Class를 상속받아 제목과 내용에 대한 사용자 입력을 받는 ArticleForm을 정의합니다. (앱 폴더에 forms.py 직접 생성)

# articles/forms.py
from django import forms

class ArticleForm(forms.Form):
    title = forms.CharField(max_length=10)
    content = forms.CharField()

1-4Form class가 대체하는 것

개발자 도구로 렌더링 결과를 보면, Form class가 label과 input을 자동으로 생성했고, 유효성 속성(maxlength="10", required)까지 붙여 줍니다. <form> 태그, csrf_token, 제출 버튼은 직접 작성합니다.

<input type="hidden" name="csrfmiddlewaretoken" value="...">
<label for="id_title">Title:</label>
<input type="text" name="title" maxlength="10" required id="id_title">
<label for="id_content">Content:</label>
<input type="text" name="content" required id="id_content">

1-5Widgets

Widgets — 폼 필드를 화면에 표시하는 HTML 입력 요소를 정의하는 구성요소. HTML 'input' element의 표현을 담당합니다.

Django Form의 widgets은 각 필드가 HTML에서 어떻게 렌더링될지를 결정합니다. 예를 들어, TextInput, Select, CheckboxInput 등 다양한 위젯 클래스를 사용해 입력 방식과 속성을 세부 조정할 수 있습니다.

# articles/forms.py
class ArticleForm(forms.Form):
    title = forms.CharField(max_length=10)
    content = forms.CharField(widget=forms.Textarea)   # 한 줄 input → 여러 줄 textarea
Widget은 단순히 input 요소의 속성 및 출력되는 부분을 변경하는 것이며, 유효성 검사와는 관계없습니다.

https://docs.djangoproject.com/ko/5.2/ref/forms/widgets/#built-in-widgets

Django ModelForm

Form vs ModelForm · ModelForm class · Meta class · fields / exclude · 주의사항

2-1Form vs. ModelForm

FormModelForm
사용자 입력 데이터를 DB에 저장하지 않을 때 (ex. 검색, 로그인)사용자 입력 데이터를 DB에 저장해야 할 때 (ex. 게시글 작성, 회원가입)

ModelForm — Model과 연결된 Form을 자동으로 생성해주는 기능을 제공. ModelForm은 Form 클래스와 Model 클래스를 결합한 형태로, 모델 필드를 기반으로 입력 폼을 자동 생성해 줍니다. 데이터 수집과 저장 과정을 동시에 처리할 수 있도록 도와줍니다.

2-2ModelForm class 정의

# articles/forms.py
from django import forms
from .models import Article

class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article
        fields = '__all__'

렌더링 결과: title은 input type="text" maxlength="10", content는 모델의 TextField에 맞춰 textarea가 자동으로 생성됩니다. created_at, updated_at은 자동 입력 필드라 form에 나오지 않습니다.

2-3Meta class

  • ModelForm의 정보를 작성하는 곳
  • Meta class는 ModelForm 내부에서 어떤 모델과 연결할지, 어떤 필드를 사용할지 등을 정의하는 설정 공간
  • 폼의 동작 방식을 제어하는 핵심 역할
'fields' 및 'exclude' 속성
class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article
        fields = ('title',)        # 포함할 필드

class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article
        exclude = ('title',)       # 제외할 필드

exclude 속성을 사용하여 모델에서 포함하지 않을 필드를 지정할 수도 있습니다.

2-4Meta class 주의사항

Django에서 ModelForm에 대한 추가 정보나 속성을 작성하는 클래스 구조를 Meta 클래스로 작성했을 뿐이며, 파이썬의 inner class와 같은 문법적인 관점으로 접근하지 말 것. 문법상 클래스 안의 클래스(inner class)가 맞지만, 상속하거나 객체를 만드는 용도가 아니라 설정을 적어두는 공간으로 이해하기.

ModelForm 적용 · save 메서드

create · is_valid() · 에러 메시지 출력 · edit · update · save()의 생성/수정 구분

3-1ModelForm을 적용한 create 로직

# articles/views.py
from .forms import ArticleForm

def create(request):
    form = ArticleForm(request.POST)
    if form.is_valid():
        article = form.save()
        return redirect('articles:detail', article.pk)
    context = {
        'form': form,
    }
    return render(request, 'articles/new.html', context)

제목 input에 스페이스바로 공백만 입력 후 제출 시 에러 메시지 출력 확인 → 유효성 검사의 결과: * This field is required.

Tip — 아무것도 입력하지 않고 제출하면 Django보다 브라우저가 먼저 "이 입력란을 작성하세요"라고 막습니다. Form이 input에 required 속성을 자동으로 붙여주기 때문입니다. 공백만 입력하면 브라우저 검사는 통과하지만, Django가 앞뒤 공백을 제거한 뒤 빈 값으로 판단해 에러를 돌려줍니다.

3-2is_valid()

여러 유효성 검사를 실행하고, 데이터가 유효한지 여부를 Boolean으로 반환합니다.

공백 데이터가 유효하지 않은 이유와 에러메시지가 출력되는 과정
  • 별도로 명시하지 않았지만 모델 필드에는 기본적으로 빈 값은 허용하지 않는 제약조건이 설정되어 있었음 (blank=False)
  • 빈 값은 is_valid()에 의해 False로 평가되고 form 객체에는 그에 맞는 에러 메시지가 포함되어 다음 코드로 진행됨 (context에 담겨 new.html을 다시 렌더링)

3-3ModelForm을 적용한 edit · update 로직

# articles/views.py
def edit(request, pk):
    article = Article.objects.get(pk=pk)
    form = ArticleForm(instance=article)
    context = {
        'article': article,
        'form': form,
    }
    return render(request, 'articles/edit.html', context)

def update(request, pk):
    article = Article.objects.get(pk=pk)
    form = ArticleForm(request.POST, instance=article)
    if form.is_valid():
        form.save()
        return redirect('articles:detail', article.pk)
    context = {
        'article': article,
        'form': form,
    }
    return render(request, 'articles/edit.html', context)
<!-- articles/edit.html -->
<form action="{% url 'articles:update' article.pk %}" method="POST">
  {% csrf_token %}
  {{ form }}
  <input type="submit">
</form>

3-4save 메서드

데이터베이스 객체를 만들고 저장하는 ModelForm의 인스턴스 메서드. form 데이터가 유효한 경우, save() 메서드를 호출하면 모델 인스턴스를 생성하고 저장됩니다. instance 인자를 통해 새 객체 생성과 기존 객체 수정도 구분할 수 있습니다. 이 과정을 통해 SQL을 작성하지 않고도 데이터를 저장할 수 있습니다.

# CREATE
form = ArticleForm(request.POST)
form.save()

# UPDATE
form = ArticleForm(request.POST, instance=article)
form.save()

save() 메서드가 생성과 수정을 구분하는 법 — 키워드 인자 instance 여부를 통해 생성할지, 수정할지를 결정합니다.

HTTP 요청 다루기

view 함수 구조 변화 · new & create 결합 · edit & update 결합 · 기존 코드 정리

4-1View 함수 구조 변화

"new는 GET method 요청만을, create는 POST method 요청만을 처리" → HTTP request method 차이점을 활용해 동일한 목적을 가지는 2개의 view 함수를 하나로 구조화합니다.

요청의미
(GET) articles/create/게시글 생성 문서를 줘!
(POST) articles/create/게시글을 생성해줘!

4-2new & create 함수 결합 — 새로운 create view 함수

# articles/views.py
def create(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            article = form.save()
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm()
    context = {
        'form': form,
    }
    return render(request, 'articles/new.html', context)
  1. new와 create view 함수의 공통점과 차이점을 기반으로 하나의 함수로 결합
  2. 두 함수의 유일한 차이점이었던 request method에 따른 분기
  3. POST일 때는 과거 create 함수 구조였던 객체 생성 및 저장 로직 처리
  4. POST가 아닐 때는 과거 new 함수에서 진행했던 form 인스턴스 생성
  5. context에 담기는 form은 ① is_valid()를 통과하지 못해 에러메시지를 담은 form이거나 ② else 문을 통한 form 인스턴스
왜 request.method == 'POST'를 먼저 검사할까? — DB에 영향을 주는 POST를 명시적으로 확인하고, 그 외(GET 등)는 모두 페이지 제공으로 처리하기 위함입니다.

4-4edit & update 함수 결합 — 새로운 update view 함수

# articles/views.py
def update(request, pk):
    article = Article.objects.get(pk=pk)
    if request.method == 'POST':
        form = ArticleForm(request.POST, instance=article)
        if form.is_valid():
            form.save()
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm(instance=article)
    context = {
        'article': article,
        'form': form,
    }
    return render(request, 'articles/update.html', context)
  • 사용하지 않는 edit url 제거 (# path('<int:pk>/edit/', ...))
  • edit 관련 키워드를 update로 변경 (edit.html → update.html, 링크와 action을 articles:update로)

5-2Widgets 응용

# articles/forms.py
class ArticleForm(forms.ModelForm):
    title = forms.CharField(
        label='제목',
        widget=forms.TextInput(
            attrs={
                'class': 'my-title',
                'placeholder': 'Enter the title',
            }
        ),
    )
    content = forms.CharField(
        label='내용',
        widget=forms.Textarea(
            attrs={
                'class': 'my-content',
                'placeholder': 'Enter the content',
                'rows': 5,
                'cols': 50,
            }
        ),
        error_messages={'required': '내용을 입력해주세요.'},
    )

    class Meta:
        model = Article
        fields = '__all__'
필드를 직접 선언하면 모델에서 자동으로 가져오던 설정(label, max_length 등)을 직접 다시 써야 합니다. attrs의 maxlength는 브라우저 입력 제한일 뿐이므로, 서버 검증까지 원하면 forms.CharField(max_length=10, ...)처럼 써야 합니다.

# articles/views.py
from django.shortcuts import render, redirect
from .forms import ArticleForm
from .models import Article

def index(request):
    articles = Article.objects.all().order_by('-pk')   # 최신 글 위로
    context = {'articles': articles}                    # 템플릿에 넘길 데이터(dict)
    return render(request, 'articles/index.html', context)

def create(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)        # 사용자 입력 담은 양식
        if form.is_valid():                     # 유효성 검사
            article = form.save()               # DB 저장 + 저장된 객체 반환
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm()                    # 빈 양식
    context = {'form': form}
    return render(request, 'articles/create.html', context)

def detail(request, pk):
    article = Article.objects.get(pk=pk)        # pk: URL <int:pk>에서 전달된 값, 해당 글 1개 조회
    context = {'article': article}
    return render(request, 'articles/detail.html', context)

def update(request, pk):
    article = Article.objects.get(pk=pk)
    if request.method == 'POST':
        form = ArticleForm(data=request.POST, instance=article)   # 입력값 + 기존 글
        if form.is_valid():
            form.save()
            return redirect('articles:detail', pk)
    else:
        form = ArticleForm(instance=article)                      # 기존 글이 채워진 양식
    context = {'form': form}
    return render(request, 'articles/update.html', context)

def delete(request, pk):
    if request.method == 'POST':
        article = Article.objects.get(pk=pk)
        article.delete()
    return redirect('articles:index')
create 분기상황form
GET작성 화면 요청ArticleForm() 빈 양식
POST글쓰기 버튼 클릭ArticleForm(request.POST) 입력값 담긴 양식
POST + 검증 실패is_valid() Falseif 밖으로 내려와 에러 포함 양식 다시 렌더
  • redirect('articles:detail', article.pk): 새 글 상세 페이지로 이동 (새로고침 중복 저장 방지)
  • update의 instance=article: 새 글 생성이 아닌 기존 글 수정. GET에서도 instance 전달 → 양식에 원래 내용 미리 채움
  • delete는 POST일 때만 삭제 → 주소창 직접 입력(GET)으로는 삭제 불가. 버튼은 detail.html에 위치, 처리 후 목록으로 redirect

확인문제 (원본 슬라이드 수록)

문제를 먼저 풀고, 눌러서 정답과 해설을 확인하세요

1. 다음 중 Django Form이 하는 일로 적절하지 않은 것은?
  1. 데이터 유효성 검사
  2. 데이터 자동 저장 처리
  3. 데이터베이스에 접속하여 직접 테이블 삭제
  4. 입력 화면 생성
정답 · 해설 보기
c) — Django Form은 사용자로부터 입력받은 데이터의 화면 표시, 유효성 검사, 데이터 처리를 담당하지만, 데이터베이스의 테이블을 직접 삭제하는 기능은 제공하지 않습니다. 테이블 삭제와 같은 작업은 데이터베이스 관리자의 권한으로 수행되며 Form 클래스와는 관련이 없습니다.
2. ModelForm과 일반 Form의 차이에 대해 옳은 것은?
  1. ModelForm은 DB와 연결되지 않는다.
  2. 일반 Form은 DB에 데이터를 저장할 때 사용한다.
  3. ModelForm은 Model과 연결되어 있어 입력 데이터를 DB에 저장할 수 있다.
  4. 일반 Form은 자동 유효성 검사를 지원하지 않는다.
정답 · 해설 보기
c) — ModelForm은 Django의 모델(Model)과 직접 연결되어 있어 데이터베이스에 저장하거나 수정할 때 편리하게 사용할 수 있습니다. 일반 Form은 Model과 연결되지 않고 단지 입력값 수집 및 유효성 검사만 처리합니다.
3. 다음 중 Django Form의 유효성 검사를 수행하는 메서드는?
  1. save()
  2. is_valid()
  3. redirect()
  4. render()
정답 · 해설 보기
b) is_valid() — 사용자 입력 데이터가 유효한 형식인지 검사합니다. save()는 유효성 검사를 통과한 후 데이터를 저장할 때 사용하는 메서드입니다.
4. Form의 입력 필드를 화면에 렌더링할 때 사용하는 옵션 중, 각 필드를 <p> 태그로 감싸주는 옵션은?
  1. {{form.as_ul}}
  2. {{form.as_table}}
  3. {{form.as_p}}
  4. {{form.as_render}}
정답 · 해설 보기
c) {{form.as_p}} — 각 입력 필드를 자동으로 <p> 태그로 감싸서 출력합니다. as_ul, as_table 같은 다른 옵션도 존재하지만, <p> 태그를 사용하는 것은 as_p입니다.
5. Django에서 사용자 입력 데이터를 저장하거나 수정할 때 사용하는 메서드는?
  1. update()
  2. create()
  3. save()
  4. delete()
정답 · 해설 보기
c) save() — ModelForm의 save()로 데이터를 저장하거나 기존 데이터를 수정합니다. create(), update(), delete()는 모델(QuerySet)의 메서드로 사용될 수 있지만 Form에서 데이터를 처리할 때는 사용하지 않습니다.
6. Django Form 클래스의 기본 구조에서 HTML의 입력 요소를 조정할 때 사용하는 것은?
  1. model
  2. widget
  3. validator
  4. queryset
정답 · 해설 보기
b) widget — HTML 입력 요소의 스타일이나 추가 속성(placeholder, class 등)을 지정할 때 Widget을 사용합니다. 입력 필드가 HTML에서 어떻게 렌더링될지 세부적으로 조정할 수 있습니다.
7. Django의 ModelForm에서 사용할 필드를 선택적으로 제외할 때 사용하는 Meta 클래스 속성은?
  1. fields
  2. exclude
  3. remove
  4. drop
정답 · 해설 보기
b) exclude — exclude는 폼 생성 시 제외하고 싶은 필드를 지정하는 데 사용합니다. 반면 fields는 포함할 필드를 명시적으로 정의할 때 사용합니다.
8. 다음 중 Django Form에서 입력값이 유효하지 않을 때 발생하는 동작으로 가장 알맞은 것은?
  1. 서버가 500 에러를 반환한다.
  2. Form 객체가 생성되지 않는다.
  3. is_valid()는 False를 반환하고 오류 메시지가 form 객체에 저장된다.
  4. 잘못된 값도 그대로 저장된다.
정답 · 해설 보기
c) — 오류 내용은 form 객체의 errors 속성에 저장되어 사용자에게 표시할 수 있습니다. 이 과정은 자동으로 수행되며 서버 에러가 발생하지 않고, 잘못된 값도 저장되지 않습니다.
9. Form 위젯에서 HTML 속성(placeholder, class 등)을 설정할 수 있는 곳은?
  1. fields
  2. model
  3. attrs
  4. exclude
정답 · 해설 보기
c) attrs — 입력 필드에 추가 속성을 지정하려면 Widget 내부의 attrs 속성을 사용합니다. 이를 통해 화면에 표시되는 HTML 요소를 세부적으로 제어할 수 있습니다.
10. 다음 중 Django view 함수가 HTTP의 POST 요청을 처리하는 상황으로 올바른 것은?
  1. 화면에 폼을 출력하여 사용자에게 보여준다.
  2. 사용자가 입력한 데이터를 받아서 유효성 검사를 수행한다.
  3. 데이터베이스에 있는 데이터를 화면에 표시한다.
  4. URL 주소를 통해 직접 화면에 접근할 때 사용된다.
정답 · 해설 보기
b) — POST 요청은 사용자가 입력한 데이터를 서버로 전송하여 처리할 때 사용됩니다. 사용자가 제출한 폼 데이터를 받아 유효성 검사를 거쳐 데이터베이스에 저장하거나 처리하는 데 활용됩니다.
