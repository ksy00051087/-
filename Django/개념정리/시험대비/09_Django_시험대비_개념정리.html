가상 환경과 의존성 관리

venv · pip freeze · requirements.txt

개념가상 환경이란

프로젝트마다 독립된 파이썬 실행 환경을 만들어 패키지 버전 충돌을 막는 것. 프로젝트 A는 Django 4.2, B는 5.0을 써도 서로 영향이 없다.

# 1. 가상 환경 생성 (venv 라는 이름의 폴더 생성)
python -m venv venv
# 2. 활성화 (Windows Git Bash)
source venv/Scripts/activate
#    (macOS/Linux) source venv/bin/activate
# 3. 비활성화
deactivate

개념의존성 관리

의존성 = 프로젝트가 동작하려면 필요한 패키지 목록과 버전.

pip install django
pip list                          # 설치된 패키지 확인
pip freeze > requirements.txt     # 현재 환경 패키지 목록 기록
pip install -r requirements.txt   # 목록대로 한 번에 설치
시험 포인트 · venv 폴더는 git에 올리지 않는다(.gitignore). 대신 requirements.txt를 공유하고, 받은 사람이 가상 환경을 새로 만들어 pip install -r로 복원한다. freeze는 "기록", -r은 "설치".

03

URL과 view 함수 연결

요청 → urls.py → views.py → template → 응답

흐름요청-응답 과정

요청 (URL)→urls.py (path 매칭)→views.py (함수 실행)→template 렌더링→HttpResponse
# urls.py
from django.urls import path
from . import views
urlpatterns = [
    path('index/', views.index, name='index'),
]

# views.py
def index(request):               # 첫 번째 인자는 반드시 request
    context = {'name': 'Alice'}
    return render(request, 'articles/index.html', context)

포인트path()와 render()

  • path(URL 경로, view 함수, name) — view는 함수 객체를 넘긴다 (views.index O, views.index() X).
  • URL 경로는 앞에 /를 붙이지 않고 끝에 /를 붙인다 (Trailing Slash).
  • view 함수 첫 인자는 항상 request(HttpRequest 객체).
  • render(request, template_name, context) → HttpResponse 반환.
  • 템플릿 경로는 앱/templates/ 이후부터 작성 → articles/templates/articles/index.html이면 'articles/index.html'.
시험 포인트 · urlpatterns는 위에서부터 순서대로 비교하고 처음 일치한 path를 사용한다.

05

include 함수

URL을 앱 단위로 분리(App URL mapping)

왜URL 분리의 필요성

앱이 많아지면 프로젝트 urls.py 하나에 모든 path를 쓰기 어렵고, 같은 이름의 view(index)가 충돌한다. 그래서 각 앱에 urls.py를 만들고 프로젝트 urls.py는 include()로 연결만 한다.

# firstpjt/urls.py (프로젝트)
from django.urls import path, include
urlpatterns = [
    path('admin/', admin.site.urls),
    path('articles/', include('articles.urls')),
    path('pages/', include('pages.urls')),
]

포인트include 문법

  • include는 django.urls에서 import (path와 같이).
  • 인자는 문자열 모듈 경로 'articles.urls' (점 표기, 파일 경로 'articles/urls.py' X).
  • 앱 폴더 안의 urls.py는 자동 생성되지 않으므로 직접 만들어야 한다.
  • include 대상 모듈에는 urlpatterns 리스트가 있어야 한다.
06

include와 URL 매칭

일치한 앞부분은 잘라내고 나머지를 앱 urls.py로

동작요청 URL이 쪼개지는 방식

요청 /articles/3/→프로젝트 urls: 'articles/' 일치→남은 '3/' 를 articles.urls로 전달→'<int:pk>/' 매칭 → detail(request, pk=3)
# 프로젝트: path('articles/', include('articles.urls'))
# articles/urls.py
urlpatterns = [
    path('', views.index),               # /articles/
    path('<int:pk>/', views.detail),   # /articles/3/
    path('create/', views.create),       # /articles/create/
]
시험 포인트 · 최종 URL = 프로젝트 prefix + 앱 path. 앱 urls.py에 'articles/'를 또 쓰면 /articles/articles/가 된다. 앱 path에서 ''(빈 문자열)은 prefix 그 자체(/articles/)와 매칭.

URL 이름과 import

name 인자 · from . import views

NamingURL에 이름 붙이기

path에 name='index'를 붙이면 템플릿/뷰에서 주소 대신 이름으로 URL을 만든다. 나중에 실제 URL 경로가 바뀌어도 이름만 같으면 템플릿·redirect를 고칠 필요가 없다.

path('index/', views.index, name='index')
# URL 경로를 'home/'으로 바꿔도 {% url 'index' %} 는 그대로 동작

# articles/urls.py
from django.urls import path
from . import views       # '.' = 현재 패키지(articles)

# 프로젝트 urls.py에서 여러 앱 views를 직접 쓸 때는 별칭
from articles import views as article_views
from pages import views as page_views
시험 포인트 · 앱 urls.py 안에서는 from . import views. 두 앱의 views를 같은 이름으로 import하면 뒤의 것이 앞의 것을 덮어쓴다 → as 별칭 또는 include로 해결.

DTL url 태그와 app_name

{% url 'app_name:url_name' 인자 %}

문제이름 충돌

articles 앱과 pages 앱 모두 name='index'가 있으면 {% url 'index' %}가 어느 쪽인지 모른다. → app_name으로 네임스페이스(namespace)을 준다.

# articles/urls.py

urlpatterns = [
    path('', views.index, name='index'),
    path('<int:pk>/', views.detail, name='detail'),
]

<a href="{% url 'articles:index' %}">목록</a>
<a href="{% url 'articles:detail' article.pk %}">상세</a>
{# 결과: /articles/  ,  /articles/3/ #}
  • 형식: {% url 'app_name:name' arg1 arg2 %} — 인자는 공백으로 구분.
  • Variable Routing이 있으면 인자를 꼭 넘겨야 한다.
시험 포인트 · app_name을 지정했다면 반드시 'articles:index' 형태로 써야 한다. {% url 'index' %}로 쓰면 NoReverseMatch 에러.

DTL 필터

{{ 변수|필터:인자 }} · 체이닝

표자주 나오는 필터

필터예시 → 결과
length{{ 'hello'|length }} → 5
lower / upper{{ 'Hi'|upper }} → HI
truncatechars{{ 'abcdefghij'|truncatechars:5 }} → abcd… (말줄임표 포함 5글자)
truncatewords단어 단위로 자르기
default{{ value|default:"없음" }} → 값이 False면 "없음"
date{{ article.created_at|date:"Y-m-d" }}

linebreaksbr줄바꿈(\n)을 <br>로
add{{ 3|add:2 }} → 5

규칙필터 문법 규칙

  • 파이프 | 뒤에 필터 이름, 인자는 콜론 : 뒤에 (괄호 X).
  • 인자는 하나까지만 받는다.
  • 체이닝 가능: {{ name|lower|truncatechars:3 }} → 왼쪽부터 차례로 적용.
  • | 앞뒤에 공백을 넣지 않는다.
  • 약 60개의 built-in 필터 제공.
  • 필터는 출력용 가공일 뿐 원본 데이터를 바꾸지 않는다.
시험 포인트 · {{ name|truncatechars(5) }} ✗ / {{ name|truncatechars:5 }} ✓. 필터는 {{ }} 안에서 쓰고, 태그는 {% %} 안에서 쓴다.

action · method · name 속성

구조form → URL

요청 방식과 Delete

삭제는 왜 POST로?

코드delete view

# urls.py
path('<int:pk>/delete/', views.delete, name='delete')

# views.py
def delete(request, pk):
    article = Article.objects.get(pk=pk)
    if request.method == 'POST':
        article.delete()
        return redirect('articles:index')
    return redirect('articles:detail', article.pk)

템플릿삭제 버튼은 form으로

<form action="{% url 'articles:delete' article.pk %}" method="POST">
  {% csrf_token %}
  <input type="submit" value="삭제">
</form>
시험 포인트 · <a href> 링크는 항상 GET 요청이다. 삭제를 GET으로 열어두면 URL에 접속(크롤러, 링크 클릭)만 해도 데이터가 지워진다 → 데이터를 변경하는 요청은 POST + csrf_token. view에서도 request.method == 'POST'일 때만 삭제.
15

CSRF와 403

Cross-Site Request Forgery

개념CSRF란

사이트 간 요청 위조: 사용자가 의도하지 않은 요청을, 로그인된 사용자 권한으로 공격자가 보내게 만드는 공격.

Django는 CSRF Token으로 방어한다. 서버가 템플릿에 임의의 토큰을 심고, POST 요청 시 그 토큰이 함께 오는지 CsrfViewMiddleware가 검사한다.

<form method="POST">
  {% csrf_token %}
  ...
</form>
→ <input type="hidden" name="csrfmiddlewaretoken" value="…">

에러403 Forbidden

  • POST form에 {% csrf_token %}이 없으면 → 403 Forbidden (CSRF verification failed).
  • 403 = 서버가 요청을 이해했지만 권한이 없어 거부. (404 = 리소스 없음, 405 = 허용되지 않은 메서드)
  • GET 요청에는 토큰이 필요 없다 (데이터를 변경하지 않으므로).
  • 토큰은 form 태그 안쪽에 둔다.
시험 포인트 · "POST로 보냈더니 403" → 첫 번째 원인은 csrf_token 누락.

16

migrate와 DB 테이블

makemigrations(설계도) → migrate(반영)

흐름Model → Table

# articles/models.py
class Article(models.Model):
    title = models.CharField(max_length=10)
    content = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
models.py 작성→makemigrations
(0001_initial.py 생성)→migrate
(DB에 테이블 생성)
python manage.py makemigrations
python manage.py migrate
python manage.py showmigrations          # [X] 적용 여부 확인
python manage.py sqlmigrate articles 0001  # 실행될 SQL 확인

결과생성되는 테이블

  • 테이블 이름: 앱이름_모델이름(소문자) → articles_article.
  • id 컬럼(PK, 자동 증가)은 따로 정의하지 않아도 자동 생성.
  • CharField는 max_length 필수, TextField는 길이 제한 없음.
  • auto_now_add: 최초 생성 시각만 / auto_now: 저장할 때마다 갱신.
  • 처음 migrate하면 내장 앱(admin, auth, sessions…) 테이블(auth_user, django_session 등)도 함께 생성된다.
시험 포인트 · makemigrations는 DB를 건드리지 않는다(파일만 생성). DB에 실제로 반영되는 건 migrate. models.py만 고치고 migrate를 안 하면 "no such table/column" 에러.

추가 Migrations

이미 테이블이 있는데 필드를 추가하면?

상황기존 데이터에 새 필드

이미 데이터가 있는 테이블에 NOT NULL 필드(예: created_at)를 추가하면, 기존 행에 넣을 값이 없으므로 makemigrations가 기본값을 묻는다.

ModelForm Meta exclude

model · fields · exclude

코드Meta 클래스

class ArticleForm(forms.ModelForm):

        model = Article             # 호출 X, 클래스 자체

포인트exclude 규칙

  • fields: 포함할 필드 / exclude: 제외할 필드. 보통 둘 중 하나만 사용 (같이 쓸 수는 있지만 권장 X).

ModelForm 유효성 검사 흐름

new + create 통합 view

코드create view 정석

def create(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)     # ① 데이터 바인딩
        if form.is_valid():                   # ② 유효성 검사
            article = form.save()            # ③ 저장 + 객체 반환
            return redirect('articles:detail', article.pk)
    else:
        form = ArticleForm()                 # 빈 폼
    context = {'form': form}               # ④ if/else 밖!
    return render(request, 'articles/create.html', context)

흐름세 가지 경우

경우결과
GET빈 폼 생성 → render
POST + 유효save() → redirect
POST + 무효is_valid() False → 에러 메시지를 담은 form을 그대로 render (입력값 유지)
  • is_valid()가 True면 form.cleaned_data 생성. False면 form.errors에 에러.
  • form.save(commit=False): 인스턴스만 만들고 DB 저장은 보류 → 추가 값 넣은 뒤 article.save().
시험 포인트 · context와 return render가 if/else 밖(들여쓰기 한 칸 왼쪽)에 있어야 "POST + 무효" 경우에도 응답이 나간다. 안에 넣으면 무효일 때 None 반환 → ValueError(didn't return an HttpResponse).

ImageField 저장 방식

코드모델 정의

    title = models.CharField(max_length=10)
    image = models.ImageField(blank=True, upload_to='images/')

# settings.py

포인트저장 구조

  • DB 컬럼에는 이미지 자체가 아니라 파일 경로 문자열(images/cat.jpg)이 저장된다 (varchar, 기본 max_length=100).

  • ImageField는 FileField를 상속 + 이미지 유효성 검사(Pillow).

쿠키와 세션

무상태 HTTP에서 로그인 상태를 유지하는 방법

배경HTTP 특징

  • 비연결 지향(Connectionless): 응답 후 연결을 끊는다.
  • 무상태(Stateless): 이전 요청을 기억하지 못한다 → 로그인 상태 유지 불가 → 쿠키·세션 필요.
쿠키세션
저장 위치클라이언트(브라우저)서버 (django_session 테이블)
내용key-value 작은 데이터사용자 상태 정보
연결서버가 세션을 만들고 세션 ID를 쿠키(sessionid)에 담아 보냄 → 브라우저는 이후 요청마다 쿠키를 자동 전송 → 서버가 세션 ID로 사용자 식별

세부쿠키 수명 · 사용 목적

  • 세션 쿠키: 수명 지정 X → 브라우저 종료 시 삭제.
  • 지속 쿠키: Expires/Max-Age 지정 → 그 시점까지 유지.
  • 사용 목적: 세션 관리(로그인, 장바구니), 개인화(테마, 언어), 추적(행동 분석).
  • Django 세션 쿠키 기본 유효 기간: 2주.
  • 로그아웃 = 서버 세션 데이터 삭제 + 클라이언트 세션 ID 쿠키 삭제.
시험 포인트 · 쿠키는 브라우저, 세션은 서버. 세션 ID는 쿠키에 담긴다. 쿠키는 같은 서버로 보내는 모든 요청에 자동으로 포함된다. 쿠키는 DB 대체 용도가 아니다.

포인트instance의 의미

  • instance=: "이 기존 객체를 대상으로 폼을 만들어라".
  • GET: Form(instance=obj) → 기존 값이 채워진 폼.
  • POST: Form(request.POST, instance=obj) → 기존 객체를 수정(UPDATE).
  • POST에서 instance를 빼면 save() 시 새 객체를 생성(INSERT)하려 한다 → 회원정보 수정이면 새 user 생성 시도/username 중복 에러.
  • 게시글 수정도 동일: ArticleForm(request.POST, instance=article).
  • UserChangeForm 기본 fields는 권한(is_superuser 등)까지 모두 보여주므로 fields로 제한.
시험 포인트 · 수정할 대상은 로그인한 본인 request.user. 비밀번호 변경은 PasswordChangeForm(request.user, request.POST) + user = form.save() → update_session_auth_hash(request, user)로 로그인 유지.
