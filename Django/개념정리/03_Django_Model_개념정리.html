학습 시작 — 파이썬으로 테이블 만들기

Onboarding · 학습 목표

"Django는 파이썬 문법으로 테이블을 만들고 관리합니다."

SQL을 몰라도 Model 클래스로 테이블을 설계하고, Migration으로 DB에 안전하게 반영하며, Admin Site를 통해 코드 한 줄 작성 없이 데이터 CRUD를 수행할 수 있습니다.

학습 목표
  • Django Model 클래스를 이용해 데이터베이스 테이블 구조를 설계하고 "설계도(blueprint)" 개념을 설명할 수 있다.
  • 다양한 Field type과 Field option을 지정해 컬럼의 데이터 유형과 제약 조건을 정의할 수 있다.
  • python manage.py makemigrations / migrate 두 단계로 모델 변경 사항을 안전하게 데이터베이스에 반영할 수 있다.
  • admin.site.register()로 모델을 Django Admin에 등록하여 웹 UI에서 게시글을 생성, 조회, 수정, 삭제(CRUD)할 수 있다.
  • Django 기본 DB 엔진인 SQLite의 특성과 db.sqlite3를 Git에서 제외해야 하는 이유를 설명할 수 있다.

Model

Model을 통한 DB 관리 · Model class · 상속으로 받는 기능 · 프레임워크 사고

1-1Django Model

DB의 테이블을 정의하고 데이터를 조작할 수 있는 기능들을 제공합니다. 데이터베이스와 Python 클래스(객체)로 소통합니다.

  • 개발 생산성 향상 — SQL을 몰라도, 데이터베이스에 대한 깊은 지식 없이도 쉽게 데이터 관리 가능
  • 유지보수 및 확장성 증대 — 데이터베이스 구조 변경 시에도 코드 수정 최소화, 재사용성 향상
Model을 통한 DB(데이터베이스) 관리

1-2Model class

Model class는 데이터베이스 테이블의 구조를 설계하는 '청사진(blueprint)' 역할을 합니다. 어떤 데이터(컬럼)를 저장할지, 그 데이터의 형태는 어떠할지(타입, 길이 등)를 Python 코드로 정의합니다.

# articles/models.py
from django.db import models

class Article(models.Model):
    title = models.CharField(max_length=10)
    content = models.TextField()

작성한 모델 클래스는 최종적으로 DB에 다음과 같은 테이블 구조를 만듭니다. "모델 클래스 == 테이블 설계도"

idtitlecontent
………
id 필드는 Django가 자동 생성합니다. (실제 테이블 이름은 앱이름_클래스이름 = articles_article)

1-3Model 클래스 살펴보기 — 상속

  • django.db.models 모듈의 Model이라는 부모 클래스를 상속받음
  • Model은 model에 관련된 모든 코드가 이미 작성되어 있는 클래스
  • 개발자는 가장 중요한 테이블 구조를 어떻게 설계할지에 대한 코드만 작성하도록 하기 위함 ("상속"을 활용한 프레임워크의 기능 제공)
  • "약 2000줄짜리 클래스"를 한 줄로 상속 → "우리가 추가로 쓴 건 단 몇 줄, Django가 써둔 건 수천 줄"

models.Model(Django가 만들어둔 부모 클래스)이 제공하는 것: 테이블 자동 생성(Migrations) · SQL 자동 변환 · 데이터 저장/조회/수정/삭제 · 필드 유효성 검사 · id 필드 자동 생성

https://github.com/django/django/blob/main/django/db/models/base.py

1-4프레임워크 없이 직접 만든다면?

# 순수 Python으로 작성하려면
import sqlite3
conn = sqlite3.connect('db.sqlite3')
cursor = conn.cursor()
cursor.execute('''
CREATE TABLE IF NOT EXISTS article (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(10) NOT NULL,
    content TEXT NOT NULL
)
''')
conn.commit()
conn.close()

# 프레임워크의 도움을 받으면
class Article(models.Model):
    title = models.CharField(max_length=10)
    content = models.TextField()

"DB 연결, SQL 작성, 저장은 models.Model이 대신. 개발자는 테이블 구조 설계에만 집중" — 이것이 프레임워크입니다.

1-5코드 한 줄에 담긴 두 가지 "가져다 쓰기"

class Article(models.Model):                   # 1) 클래스를 "상속"받아 기능을 물려받음
    title = models.CharField(max_length=10)    # 2) 만들어진 클래스를 "가져다 씀"
  • models.Model 상속으로 테이블 관련 기능 전체를 물려받음
  • models.CharField — 이것도 Django가 만들어둔 클래스. "문자열이고 최대 10자"라고 선언만 하면, DB 타입 결정·길이 검사는 CharField가 처리
사고의 전환 — 알고리즘 사고: "이 기능을 어떻게 직접 만들까?" → 프레임워크 사고: "이 기능은 이미 있다. 내 상황에 맞게 어떻게 조합하지?" 앞으로 배울 Form 등 여러 기능들도 모두 Django가 제공하는 클래스를 상속받는 같은 구조입니다.

1-6Model 클래스 구성 요소

코드 위치의미
class Article (클래스 이름)테이블 (테이블 이름이 됨)
title, content (클래스 변수명)테이블의 각 필드(열) 이름
models.CharField(...) (Model Field)데이터베이스 테이블의 열(column)을 나타내는 중요한 구성 요소. "데이터의 유형"과 "제약 조건"을 정의
Tip — CharField의 max_length 지정은 SQLite에서는 선택 사항입니다. SQLite는 문자열 길이를 DB 차원에서 강제하지 않기 때문에, 길이 검사는 Django의 Form 등에서 처리합니다. 다른 DB(MySQL 등)에서는 필수이므로, 항상 명시하는 습관을 들이세요.

유효성 검사 — 수집한 데이터가 정확하고 유효한지 확인하는 과정 (특정 규칙이나 조건에 따라 데이터의 정확성을 확인)

Model Field

Field types · CharField vs TextField · 주요 필드 유형 · Field options · 제약 조건

2-1Model Field란?

DB 테이블의 필드(열)를 정의하며, 해당 필드에 저장되는 데이터 타입(Field types)과 제약 조건(Field options)을 정의합니다. Django는 이러한 필드 정의를 바탕으로 데이터베이스 컬럼을 만들고, 유효성 검사 등 필요한 기능을 제공합니다. 정확한 필드 정의는 애플리케이션의 안정성과 직결됩니다.

  1. Field types (필드 유형) — 데이터베이스에 저장될 "데이터의 종류"를 정의
  2. Field options (필드 옵션) — 필드의 "동작"과 "제약 조건"을 정의
title = models.CharField(max_length=10)
#              └ Field type ┘ └ Field option ┘

2-2Field types

CharField, TextField도 Django가 만들어둔 클래스입니다. 우리는 클래스를 가져다 쓰면서 옵션(max_length 등)만 지정합니다.

  • CharField() — 제한된 길이의 문자열을 저장. max_length는 SQLite에서는 생략 가능하지만 명시 권장. 예: 이름, 제목, 이메일처럼 짧고 길이를 예상할 수 있는 값
  • TextField() — 길이 제한이 없는 대용량 텍스트를 저장 (무한대는 아니며 사용하는 시스템에 따라 달라짐)

2-3CharField vs TextField, 언제 무엇을 쓸까?

구분CharFieldTextField
길이짧고 예상 가능길거나 예상하기 어려움
max_length지정 (권장)지정하지 않음
예시이름, 제목, 이메일게시글 본문, 상품 설명
Tip — 값이 255자를 넘을 것 같다면 TextField를 먼저 고려하세요.

2-5Field options

필드의 "동작"과 "제약 조건"을 정의합니다. (max_length=10처럼 필드 클래스의 인자로 전달)

제약 조건이란? — 특정 규칙을 강제하기 위해 테이블의 열이나 행에 적용되는 규칙이나 제한사항. 숫자만 저장되도록 제한을 두거나, 문자가 100자까지만 저장되도록 하는 등의 제한 조건을 의미합니다.

옵션의미기본값
null데이터베이스에서 NULL 값을 허용할지 여부를 결정False
blankform에서 빈 값을 허용할지 여부를 결정False
default필드의 기본값을 설정—

DB에서 제약조건을 설정하는 방법은 DB 수업에서 학습 · https://docs.djangoproject.com/en/5.2/ref/models/fields/#field-options

Migrations

model 변경사항을 DB에 반영 · makemigrations · migrate · 미적용 경고 · 추가 필드 migration

3-1Migrations

model 클래스의 변경사항(필드 생성, 수정, 삭제 등)을 DB에 최종 반영하는 방법입니다.

model class (설계도 초안)— makemigrations →migration 파일 0001_initial.py (최종 설계도)— migrate →db.sqlite3 테이블

3-2모델 정의부터 migration 파일 생성까지

$ python manage.py makemigrations
Migrations for 'articles':
  articles/migrations/0001_initial.py
    + Create model Article
  • 모델 클래스 작성/수정 — Django에서는 Python 클래스로 정의 (CharField: 제한된 길이의 문자열 저장, TextField: 길이 제한 없는 대용량 텍스트)
  • 마이그레이션 파일 생성 명령어 — Python 코드로 된 migration 파일(설계도)을 만드는 방법. 모델 변경을 감지하고 migration 파일을 생성하는 명령
  • migration 파일 == 최종 설계도

3-3migration 파일을 DB에 반영하기

$ python manage.py migrate
  • 마이그레이션 파일은 모델 변경사항을 기록한 Python 코드. DB 테이블 변경 내역을 순차적으로 저장하여 추적 관리합니다
  • migrate 명령은 마이그레이션 파일의 Python 코드를 SQL 문으로 자동 변환: Python 코드 → SQL 쿼리문 → 데이터베이스 실행
  • 결과: articles_article 테이블 생성 (id, title, content)

3-4Migrations 핵심 명령어 2가지

명령어역할
python manage.py makemigrationsmodel class를 기반으로 최종 설계도(migration)를 작성
python manage.py migrate최종 설계도를 DB에 전달하여 반영
Tip — 마이그레이션 파일은 되도록이면 직접 건드리지 마세요! migrations 폴더에 자동으로 생성된 파일들은 직접 수정하거나 삭제하지 않는 것이 원칙입니다.

3-5Migration 경고 메시지

Django 서버를 시작할 때 출력되는 migration 관련 경고입니다. 프로젝트 실행 시 미적용 마이그레이션 파일이 있을 때 나타납니다.

You have 18 unapplied migration(s). Your project may not work properly until you apply the
migrations for app(s): admin, auth, contenttypes, sessions.
Run 'python manage.py migrate' to apply them.
  • 경고 메시지에 명시된 대로 python manage.py migrate 명령을 실행
  • 최신 모델 변경 사항이 데이터베이스에 반영되지 않아 프로젝트가 제대로 작동하지 않을 수 있음

3-6추가 Migrations — 이미 생성된 테이블에 필드를 추가해야 한다면?

  • 이미 기존 테이블이 존재하는 경우, 새 필드를 추가할 때 문제가 발생
  • 기존에 레코드가 있는 테이블에 새로운 필드를 추가하면 기존 레코드는 어떤 값으로 채울지 결정해야 함
  • Django는 makemigrations 실행 시 기본값 설정을 요구하는 프롬프트를 띄움
# articles/models.py
class Article(models.Model):
    title = models.CharField(max_length=10)
    content = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
DateTimeField 옵션 (optional)동작
auto_now데이터가 저장될 때마다 자동으로 현재 날짜시간을 저장
auto_now_add데이터가 처음 생성될 때만 자동으로 현재 날짜시간을 저장
$ python manage.py makemigrations

Migrations for 'articles':
  articles/migrations/0002_article_created_at_article_updated_at.py
    + Add field created_at to article
    + Add field updated_at to article
  • 1번은 현재 대화를 유지하면서 직접 기본 값을 입력하는 방법, 2번은 현재 대화에서 나간 후 models.py에 기본 값 관련 설정을 하는 방법
  • 입력한 기본값은 기존의 모든 데이터 행에 적용됩니다
  • 날짜 데이터이기 때문에 직접 입력하기보다 Django가 제안하는 기본 값을 사용하는 것을 권장 (Enter → timezone.now)
  • migrations 과정 종료 후 2번째 migration 파일이 생성됨. Django는 설계도를 쌓아가면서 추후 문제가 생겼을 시 복구하거나 되돌릴 수 있도록 함 (마치 'git commit'과 유사)
  • migrate 후 테이블: id, title varchar(10), content TEXT, created_at datetime, updated_at datetime

3-7언제 Migration이 필요할까?

model class에 변경사항(1)이 생겼다면, 반드시 새로운 설계도를 생성(2)하고, 이를 DB에 반영(3)해야 한다.

(1) model class 생성/수정→(2) makemigrations→(3) migrate

Admin site

Automatic admin interface · createsuperuser · 모델 등록 · 데이터 생성·수정·삭제

4-1Automatic admin interface

Django가 추가 설치 및 설정 없이 자동으로 제공하는 관리자 인터페이스입니다.

  • 추가 설정 없이 자동 생성되는 웹 기반 관리 도구
  • 주요 기능: 데이터베이스 모델의 CRUD(생성, 읽기, 업데이트, 삭제) 작업을 간편하게 수행
  • 활용: 빠른 프로토타이핑, 비개발자 데이터 관리, 내부 시스템 구축에 이상적

4-21~2. admin 계정 생성

# manage.py 파일이 있는 위치에서 진행
$ python manage.py createsuperuser

데이터베이스 초기화 · Migrations 기타 명령어 · 최초 migrate 출력 · SQLite

5-1데이터베이스 초기화

  1. migration 파일 삭제 — makemigrations 명령어로 생성되는 파일들 (0001_initial.py, 0002_...py)
  2. db.sqlite3 파일 삭제
삭제 금지 — migrations 폴더 자체와 __init__.py 파일은 지우면 안 됩니다.

5-2Migrations 기타 명령어

# migrations 파일들이 migrate 됐는지 안됐는지 여부를 확인 ([X] 표시 = migrate 완료)
$ python manage.py showmigrations

# 해당 migrations 파일이 SQL 언어(DB에서 사용하는 언어)로 어떻게 번역되어 DB에 전달되는지 확인
# python manage.py sqlmigrate <앱 이름> <마이그레이션 이름>
$ python manage.py sqlmigrate articles 0001

5-3최초 migrate 시 출력 내용이 많은 이유는?

Django 프로젝트가 동작하기 위해 미리 작성되어 있는 기본 내장 앱들(INSTALLED_APPS의 admin, auth, contenttypes, sessions …)에 대한 migration 파일들이 함께 migrate 되기 때문입니다.

Operations to perform:
  Apply all migrations: admin, articles, auth, contenttypes, sessions
Running migrations:
  Applying contenttypes.0001_initial... OK
  Applying auth.0001_initial... OK
  Applying admin.0001_initial... OK
  Applying articles.0001_initial... OK
  ... (auth.0002 ~ auth.0012, sessions.0001 등)

5-4SQLite란?

데이터베이스 관리 시스템 중 하나이며 Django의 기본 데이터베이스로 사용됩니다.

  • 파일 기반 — 데이터베이스가 하나의 파일로 저장되어, 설치/설정 없이 간편하게 복사/이동/백업 가능
  • 가볍고 빠름 — 별도 서버 없이 파일로 직접 데이터 처리. 소규모 서비스나 모바일 환경에 최적화
  • 호환성 — 다양한 운영체제와 프로그래밍 언어에서 폭넓게 사용 가능

5-5SQLite 주의사항 — .gitignore

  • db.sqlite3 파일은 Git 등 버전 관리 시스템에서 관리하지 않는 것이 원칙
    • 데이터가 변경될 때마다 파일 전체가 변경됨
    • SQLite 파일은 로컬 컴퓨터에 저장된 데이터 기록
  • .gitignore 파일에 db.sqlite3를 추가하여 Git 버전 관리에서 제외해야 함
  • .gitignore — Git이 특정 파일이나 폴더를 추적하지 않도록 설정하는 파일
  • gitignore.io — 개발자들이 .gitignore 파일을 쉽게 만들 수 있도록 도와주는 웹 서비스. Django를 기술하면 db.sqlite3가 자동으로 포함됨

이 문서의 큰 줄기

  • Model 클래스 = DB 설계도. models.Model을 상속해 필드를 파이썬 코드로 정의하면 그 코드가 곧 테이블 청사진. DB 연결·SQL 작성은 Django가 대신하고 개발자는 테이블 구조 설계에만 집중한다 — 이것이 프레임워크의 기능 제공 방식.
  • Field type & option으로 컬럼의 데이터 형태와 규칙을 명확히 지정.
  • 마이그레이션 두 단계: 모델 변경 → makemigrations(설계도 생성) → migrate(DB 적용). 변경 이력은 파일로 관리된다.
  • Admin Site로 즉시 CRUD: admin.site.register(Article) 후 /admin에서 게시글 생성·조회·수정·삭제.
