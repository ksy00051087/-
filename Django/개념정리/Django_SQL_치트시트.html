비교AB
WHERE vs HAVING개별 행, GROUP BY 이전그룹, GROUP BY 이후
DELETE vs DROP TABLE레코드 삭제테이블(구조+데이터) 삭제
= NULL vs IS NULLUNKNOWN(의도대로 동작 안 함)올바른 NULL 비교
INNER JOIN vs LEFT JOIN양쪽에 모두 일치하는 행만왼쪽 전부 + 일치 없으면 NULL
FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT
SELECT Composer, AVG(Milliseconds / 60000) AS avgOfMinute
FROM tracks
GROUP BY Composer
HAVING avgOfMinute < 10;        -- 집계 조건은 WHERE가 아니라 HAVING

SELECT users.name FROM users
LEFT JOIN articles ON articles.userId = users.id
WHERE articles.userId IS NULL;  -- LEFT JOIN + IS NULL = "~한 적 없는"

직렬화 · 수정 방식 · 읽기 전용 · 삭제 응답 · 404 · 역참조 이름

비교AB
Serialization vs Serializer과정(번역): serializer.data를 꺼낼 때 일어남도구(번역가): serializers.py에 작성하는 클래스
PUT vs PATCH전체 교체, 모든 필수 필드 필요 (partial=False)일부 수정, 보낸 필드만 (partial=True 필수)
read_only_fields vs read_only=TrueMeta 안, 기존 필드를 그대로 응답 전용으로필드 선언 시, 재정의·새로 추가한 필드 (read_only_fields가 안 먹음)
DELETE 204 vs 200기본: 본문 없이 Response(status=204)삭제 정보를 돌려줄 때만 Response(data, status=200)
get() vs get_object_or_404()없으면 DoesNotExist → 500없으면 Http404 → 404
comment_set vs Count('comment')Serializer 필드 이름 = 역참조 매니저명annotate 조회 이름 = 소문자 모델명 (related_name 지정 시 둘 다 그 이름)
GET 200·POST 201 / 실패 400·PUT·PATCH 200·DELETE 204·없음 404·막힌 메서드 405
@api_view(['GET', 'POST'])
def article_list(request):
    if request.method == 'GET':
        articles = Article.objects.all()
        serializer = ArticleListSerializer(articles, many=True)   # QuerySet이면 many=True
        return Response(serializer.data)
    elif request.method == 'POST':
        serializer = ArticleSerializer(data=request.data)
        if serializer.is_valid(raise_exception=True):             # 실패 시 자동 400
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)

# 댓글 생성: FK는 view에서 넣고, Serializer에서는 read_only
serializer.save(article=article)

# 댓글 개수: view에서 annotate, Serializer에서 SerializerMethodField
article = get_object_or_404(Article.objects.annotate(num_of_comments=Count('comment')), pk=article_pk)
def get_num_of_comments(self, obj):
    if hasattr(obj, 'num_of_comments'):
        return obj.num_of_comments
    return obj.comment_set.count()
