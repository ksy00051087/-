1
큐(Queue)의 개념과 특성
선입선출 · front/rear · 기본 연산 · 연산 과정

  




1-1큐의 특성


  • 스택과 마찬가지로 삽입과 삭제의 위치가 제한적인 자료구조 — 큐의 뒤(rear)에서는 삽입만 하고, 큐의 앞(front)에서는 삭제만 이루어지는 구조입니다.
  • 선입선출구조 (FIFO: First In First Out) — 가장 먼저 넣은 자료가 가장 먼저 나오는 것. 예를 들어 큐에 1, 2, 3을 차례대로 넣으면 꺼낼 때도 1, 2, 3이 순서대로 나오게 됩니다.
  • 큐의 또 다른 예로는 서비스 대기행렬이 있습니다.
용어의미
선형구조자료 간의 관계가 1:1의 관계를 갖는다.
front (머리)저장된 원소 중 첫 번째 원소 (또는 삭제된 위치)
rear (꼬리)저장된 원소 중 마지막 원소






1-2큐의 기본 연산


연산기능
enQueue(item)큐의 뒤쪽(rear 다음)에 원소를 삽입하는 연산
deQueue()큐의 앞쪽(front)에서 원소를 삭제하고 반환하는 연산
createQueue()공백 상태의 큐를 생성하는 연산
isEmpty()큐가 공백상태인지를 확인하는 연산
isFull()큐가 포화상태인지를 확인하는 연산
Qpeek()큐의 앞쪽(front)에서 원소를 삭제 없이 반환하는 연산






1-3큐의 연산 과정


① 공백 큐 생성 : createQueue()        front = rear = -1   [ _ , _ , _ ]
② 원소 A 삽입 : enQueue(A)            front=-1 rear=0     [ A , _ , _ ]
③ 원소 B 삽입 : enQueue(B)            front=-1 rear=1     [ A , B , _ ]
④ 원소 반환/삭제 : deQueue()  → A     front=0  rear=1     [ _ , B , _ ]
⑤ 원소 C 삽입 : enQueue(C)            front=0  rear=2     [ _ , B , C ]
⑥ 원소 반환/삭제 : deQueue()  → B     front=1  rear=2     [ _ , _ , C ]
⑦ 원소 반환/삭제 : deQueue()  → C     front=2  rear=2     [ _ , _ , _ ]  (공백)



  





  
2
선형 큐
1차원 배열 · 초기·공백·포화 상태 · enQueue/deQueue/isEmpty/isFull/Qpeek · 구현 · 문제점

  




2-1선형 큐 — 1차원 배열을 이용한 큐


  • 큐의 크기 = 배열의 크기
  • front: 마지막으로 삭제된 인덱스 (저장된 첫 번째 원소의 바로 앞)
  • rear: 저장된 마지막 원소의 인덱스
상태 표현
상태조건
초기 상태front = rear = -1
공백 상태front == rear
포화 상태rear == n-1 (n: 배열의 크기, n-1: 배열의 마지막 인덱스)






2-2삽입 enQueue(item) · 삭제 deQueue()



enQueue: 마지막 원소 뒤에 새로운 원소를 삽입하기 위해 ① rear 값을 하나 증가시켜 새로운 원소를 삽입할 자리를 마련하고 ② 그 인덱스에 해당하는 배열원소 Q[rear]에 item을 저장.


deQueue: 가장 앞에 있는 원소를 삭제하기 위해 ① front 값을 하나 증가시켜 큐에 남아 있는 첫 번째 원소로 이동 ② 새로운 첫 번째 원소를 리턴함으로써 삭제와 동일한 기능함.


isEmpty: front == rear 이면 공백. isFull: rear == n-1 이면 포화. Qpeek: 현재 front의 한 자리 뒤(front+1)에 있는 원소, 즉 큐의 첫 번째에 있는 원소를 반환.

2-4선형 큐 이용 시의 문제점 — 잘못된 포화상태 인식


  • 선형 큐를 이용하여 원소의 삽입과 삭제를 계속할 경우, 배열의 앞부분에 활용할 수 있는 공간이 있음에도 불구하고, rear = n-1인 상태 즉, 포화상태로 인식하여 더 이상의 삽입을 수행하지 않게 됨
  • 해결 방법 1 — 매 연산이 이루어질 때마다 저장된 원소들을 배열의 앞부분으로 모두 이동시킴: 원소 이동에 많은 시간이 소요되어 큐의 효율성이 급격히 떨어짐
  • 해결 방법 2 — 1차원 배열을 사용하되, 논리적으로는 배열의 처음과 끝이 연결되어 원형 형태의 큐를 이룬다고 가정하고 사용 → 원형 큐



  





  
3
원형 큐
초기 공백 상태 · 인덱스 순환(mod) · front 자리 비우기 · 선형 vs 원형 · 구현

  




3-1원형 큐의 구조


  • 초기 공백 상태: front = rear = 0
  • Index의 순환: front와 rear의 위치가 배열의 마지막 인덱스인 n-1를 가리킨 후, 그 다음에는 논리적 순환을 이루어 배열의 처음 인덱스인 0으로 이동해야 함 — 이를 위해 나머지 연산자 mod를 사용함
  • front 변수: 공백 상태와 포화 상태 구분을 쉽게 하기 위해 front가 있는 자리는 사용하지 않고 항상 빈자리로 둠
삽입 위치삭제 위치
선형큐rear = rear + 1front = front + 1
원형큐rear = (rear + 1) mod nfront = (front + 1) mod n






3-2원형 큐의 상태와 연산


연산설명
공백상태front == rear
포화상태삽입할 rear의 다음 위치 == 현재 front — (rear + 1) mod n == front
enQueue(item)rear 값을 조정하여 새로운 원소를 삽입할 자리를 마련함: rear ← (rear + 1) mod n; 그 인덱스에 해당하는 배열원소 cQ[rear]에 item을 저장
deQueue()front 값을 조정하여 삭제할 자리를 준비함: front ← (front+1) mod n; 새로운 front 원소를 리턴함으로써 삭제와 동일한 기능함
크기가 n인 원형 큐에는 front 자리를 비워 두므로 최대 n-1개까지 저장됩니다.

4-1연결 큐의 구조


  • 단순 연결 리스트(Linked List)를 이용한 큐

⑦ 원소 삭제   : deQueue();             front=null rear=null

5-1우선순위 큐 (Priority Queue)


  • 우선순위를 가진 항목들을 저장하는 큐
  • FIFO 순서가 아니라 우선순위가 높은 순서대로 먼저 나가게 됩니다.
  • 적용 분야: 시뮬레이션 시스템, 네트워크 트래픽 제어, 운영체제의 태스크 스케줄링
배열을 이용한 우선순위 큐
  • 배열을 이용하여 자료를 저장
  • 원소를 삽입하는 과정에서 우선순위를 비교하여 적절한 위치에 삽입하는 구조
  • 가장 앞에 최고 우선순위의 원소가 위치하게 됨
  • 문제점: 배열을 사용하므로, 삽입이나 삭제 연산이 일어날 때 원소의 재배치가 발생 — 이에 소요되는 시간이나 메모리 낭비가 큼
실전에서는 힙(heap)으로 구현한 heapq를 사용합니다 — 삽입/삭제 O(log n). (Tree 강의의 힙 참고)

6-1BFS — Breadth First Search


  • 너비우선탐색은 탐색 시작점의 인접한 정점들을 먼저 모두 차례로 방문한 후에, 방문했던 정점을 시작점으로 하여 다시 인접한 정점들을 차례로 방문하는 방식
  • 인접한 정점들에 대해 탐색을 한 후, 차례로 다시 너비우선탐색을 진행해야 하므로, 선입선출 형태의 자료구조인 큐를 활용함
  • 예제 그래프를 BFS로 탐색하면 시작 정점에서 가까운 순서(레벨)대로 방문 — 미로 최단 거리, 레벨 탐색, 최단 경로 문제 등에 자주 사용됨
        A
      / | \
     B  C  D        A → B C D (1단계) → E F G H I (2단계)
    / \    / \
   E   F  G   H
          |
          I






6-2BFS 알고리즘 (입력 파라미터: 그래프 G와 탐색 시작점 v)


def BFS(G, v, n):            # 그래프 G, 탐색 시작점 v
    visited = [0] * (n+1)    # n : 정점의 개수
    queue = []               # 큐 생성
    queue.append(v)          # 시작점 v를 큐에 삽입
    while queue:             # 큐가 비어있지 않은 경우
        t = queue.pop(0)     # 큐의 첫번째 원소 반환
        if not visited[t]:   # 방문되지 않은 곳이라면
            visited[t] = True    # 방문한 것으로 표시
            visit(t)             # 정점 t에서 할 일
            for i in G[t]:       # t와 연결된 모든 정점에 대해
                if not visited[i]:   # 방문되지 않은 곳이라면
                    queue.append(i)  # 큐에 넣기
개선형: 큐에 넣을 때 방문 표시를 하면 같은 정점이 큐에 중복으로 들어가지 않습니다. 이때 visited[w] = visited[t] + 1 로 저장하면 시작점으로부터의 거리가 기록됩니다.

Queue 확인문제


1. 큐(Queue)의 데이터 처리 방식은?

2. 다음 중 큐의 기본 연산이 아닌 것은?
  1. enqueue
  2. dequeue
  3. push
  4. peek
정답: push — push는 스택 연산이고, 큐는 enqueue, dequeue, peek 등을 사용합니다.
3. 다음 중 큐의 종류가 아닌 것은?
  1. 선형 큐
  2. 원형 큐
  3. 그래프 큐
  4. 우선순위 큐
정답: 그래프 큐 — 그래프 큐는 존재하지 않으며, 선형 큐, 원형 큐, 우선순위 큐는 실제 큐의 다양한 형태입니다.
4. 선형 큐의 단점은?
  1. 구현이 어렵다
  2. 사용한 공간을 재사용할 수 없다
  3. 속도가 느리다
  4. 메모리를 무제한으로 사용한다
정답: 사용한 공간을 재사용할 수 없다 — 선형 큐는 앞부분이 비어도 다시 사용할 수 없기 때문에 낭비가 생깁니다.
5. 선형 큐의 단점을 보완한 큐는? (단답형)
정답: 원형 큐
6. 우선순위 큐가 사용되는 분야는?
  1. 시뮬레이션 시스템
  2. 네트워크 트래픽 제어
  3. 운영체제 태스크 스케줄링
  4. 모두 해당
정답: 모두 해당
7. 다음 중 큐가 아닌 다른 자료구조를 사용하는 것이 적절한 것은?
  1. 프린터 대기열
  2. 명령어 실행 기록(실행 취소)
  3. 은행 번호표
  4. 키보드 버퍼
정답: 명령어 실행 기록 — 명령어 실행 기록은 후입선출 방식의 스택이 적절합니다.

  1. DFS
  2. BFS
  3. 이진 탐색
  4. 정렬
정답: BFS — 너비 우선 탐색으로, 큐를 사용해 가장 가까운 노드부터 탐색합니다.
9. 다음 중 큐가 아닌 스택 구조를 사용하는 예는?

  3. 콜센터 대기
  4. 버퍼
정답: 브라우저 뒤로가기 — 후입선출 방식의 스택 구조를 사용합니다.
10. 버퍼에서 큐를 사용하는 이유는 무엇인가요?
  1. 가장 최근 요청을 먼저 처리하기 위해
  2. 먼저 들어온 요청부터 순서대로 처리하기 위해
  3. 데이터를 한꺼번에 처리하기 위해
  4. 저장 공간을 최소화하기 위해
정답: 먼저 들어온 요청부터 순서대로 처리하기 위해 — 버퍼는 순차적인 데이터 흐름을 관리하므로 큐(FIFO) 구조가 적합합니다.
11. 파이썬 리스트로 큐를 구현할 때 dequeue에 해당하는 코드는?
  1. return q.pop()

  3. q.append(x)
  4. q.insert(0, x)
정답: return q.pop(0) — 큐는 뒤에 추가하고(append), 앞에서 제거(pop(0))하는 방식으로 동작합니다.

핵심 키워드


키워드설명예시
큐(Queue)먼저 들어온 데이터가 먼저 나가는 선입선출(FIFO) 자료구조. 삽입(enQueue), 삭제(deQueue), 공백(isEmpty), 포화(isFull) 연산. 선형 큐, 원형 큐, 연결 큐, 우선순위 큐은행 대기열
FIFO먼저 들어온 데이터가 먼저 나가는 자료 처리 방식프린터 대기열
버퍼(Buffer)입력과 출력 속도가 다른 장치 간에 데이터를 임시로 저장해주는 공간. 데이터를 모아 두었다가 순서대로 처리되도록 도와주는 중간 완충 역할. 큐를 사용하여 먼저 들어온 데이터부터 차례대로 처리함키보드 버퍼, 동영상 스트리밍
BFS그래프 탐색 기법으로, 현재 정점에 인접한 정점들을 먼저 탐색. 큐를 사용하여 탐색 순서를 유지하며, 가까운 노드부터 차례대로 방문. 미로 최단 거리, 레벨 탐색, 최단 경로 문제 등에 자주 사용됨미로 최단 거리






이 문서의 큰 줄기


  • 큐는 뒤(rear)로 넣고 앞(front)에서 꺼낸다.
  • 선형 큐는 앞 공간을 재사용하지 못한다 → 원형 큐(mod 순환), 크기 제한이 싫으면 연결 큐, 파이썬 실전은 deque.
  • 우선순위 큐는 FIFO가 아니라 우선순위 순서 — 배열 구현은 재배치 비용이 크고 힙이 효율적.
  • BFS = 큐 + visited, visited[w] = visited[t] + 1 로 최단 거리까지 얻는다.
