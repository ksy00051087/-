1-1메모리는 숫자만을 저장할 수 있습니다



그래서 A라는 글자의 모양 그대로 비트맵으로 저장하는 방법을 사용하지 않는 한(이 방법은 메모리 낭비가 심합니다), 각 문자에 대해서 대응되는 숫자를 정해 놓고 이것을 메모리에 저장하는 방법이 사용됩니다.


영어가 대소문자 합쳐서 52자이므로 6비트(64가지 경우)면 저장할 수 있습니다. 예: 'a' → 000000(0), 'b' → 000001(1), 'c' → 000010(2) 같이 6비트 이진수를 배정합니다. 이를 코드 체계라고 합니다.


코드 체계 — 컴퓨터가 처리할 수 있도록 문자에 고유한 숫자를 부여하는 것.






1-2코드체계의 문제와 개선 — ASCII


  • 네트워크가 발전되기 전 미국의 각 지역 별로 코드체계를 정해 놓고 사용.
  • 네트워크가 발전하면서 서로 정보를 주고 받을 때 정보를 달리 해석한다는 문제가 생김.
  • 그래서 혼동을 피하기 위해 표준안을 만들기로 함.
  • 1967년, 미국에서 ASCII(American Standard Code for Information Interchange)라는 문자 인코딩 표준이 제정됨.
  • ASCII는 7-bit 인코딩으로 128문자를 표현하며, 33개의 출력 불가능한 제어 문자들과 공백을 비롯한 95개의 출력 가능한 문자들로 이루어짐.

1-3확장 아스키 (Extended ASCII)


  • 표준 문자 이외의 악센트 문자, 도형 문자, 특수 문자, 특수 기호 등 부가적인 문자를 128개 추가할 수 있게 하는 부호.
  • 표준 아스키는 7-bit를 사용하여 문자를 표현, 확장 아스키는 1B 내의 8-bit를 모두 사용함으로써 추가적인 문자를 표현할 수 있음.
  • 컴퓨터 생산자와 소프트웨어 개발자가 여러 가지 다양한 문자에 할당할 수 있도록 하고 있음. 이렇게 할당된 확장 부호는 표준 아스키와 같이 서로 다른 프로그램이나 컴퓨터 사이에 교환되지 못함.
  • 표준 아스키는 마이크로컴퓨터 하드웨어 및 소프트웨어 사이에서 세계적으로 통용되는 데 비해, 확장 아스키는 프로그램이나 컴퓨터 또는 프린터가 그것을 해독할 수 있도록 설계되어 있어야만 올바르게 해독될 수 있음.






1-4유니코드 — 다국어 처리를 위한 표준


  • 컴퓨터가 발전하면서 미국뿐 아니라 각 나라에서 컴퓨터가 발전함. 각 국가들은 자국의 문자를 표현하기 위하여 코드 체계를 만들어서 사용하게 됨.
  • 우리나라도 한글 코드체계를 만들어 사용했고 조합형, 완성형 두 종류를 가지고 있었습니다.
  • 인터넷이 전 세계로 발전하면서 ASCII를 만들기 전과 같은 문제가 국가 사이에 정보를 주고받을 때 발생 — 자국의 코드체계를 타 국가가 가지고 있지 않으면 정보를 잘못 해석할 수밖에 없음.
  • 다국어 처리를 위해 표준인 유니코드를 만듦. 비영리 단체인 유니코드 컨소시엄(https://home.unicode.org)에서 관리합니다.
  • 이모지(emoji)도 유니코드 문자입니다.
  • 'A'의 유니코드는 16진수(10진수)로 0041(65)입니다. '€'의 유니코드는 16진수로 20AC(10진수 8364) — print('\u20AC') 또는 chr(8364)로 출력할 수 있습니다.

1-5유니코드의 Character Set 분류와 바이트 순서


  • UCS-2 (Universal Character Set 2), UCS-4 (Universal Character Set 4) — 유니코드를 저장하는 변수의 크기를 정의함.
  • 그러나, 바이트 순서에 대해서는 표준화하지 못했습니다.
  • 파일을 읽을 때 이 파일이 UCS-2, UCS-4인지 인식하고 각 경우를 구분해서 모두 다르게 구현해야 하는 문제가 발생.
  • 그래서 유니코드의 적당한 외부 인코딩이 필요하게 되었습니다.
바이트 단위 저장 순서 — big-endian과 little-endian
  • 여러 바이트로 이루어진 데이터를 바이트 단위로 저장하는 방식을 Endian이라고 합니다.
  • big-endian: 상위 바이트(MSB, Most Significant Byte)를 가장 낮은 주소에 저장합니다.
  • little-endian: 하위 바이트(LSB, Least Significant Byte)를 가장 낮은 주소에 저장합니다.
  • 바이트 단위 저장 순서가 정해지지 않은 경우 잘못된 해석 가능성이 있습니다.

1-7인코딩 방식 확인과 줄 바꿈 문자

2-1문자열이란?



문자들이 순서대로 나열된 데이터로, 텍스트 표현이나 처리에 사용됩니다. 문자를 차례대로 모아 놓은 것으로, 텍스트(문장, 단어, 기호 등)를 표현하거나 처리할 때 사용됩니다.


문자열의 분류
분류설명
fixed length고정 길이 문자열
variable length — Length controlledjava 언어 등. 문자열의 길이 정보를 함께 저장해서, 그 길이만큼 문자 데이터를 읽는 방식입니다.
variable length — DelimitedC 언어. 문자열의 끝을 나타내는 특정 문자(구분자)를 넣어서, 구분자가 나올 때까지 문자를 읽는 방식. C언어는 널문자(NULL, '\0')를 사용합니다.






2-2파이썬 문자열 객체의 내부 구조 (CPython)


  • PyObject_HEAD: 모든 Python 객체가 공통으로 갖는 정보(참조 횟수, 타입)
  • length: 문자열의 길이
  • hash: 문자열의 해시값으로, 딕셔너리 키로 쓸 때 사용됩니다.
  • interned: 같은 문자열을 관리하는 플래그입니다.
  • kind: 문자열 인코딩의 크기(1·2·4바이트)입니다.
  • data: 문자열이 저장된 실제 메모리 주소를 가리키는 포인터입니다.
→ 길이 정보를 함께 저장하므로 Length controlled 방식이며, len()은 O(1)입니다.






2-3C · Java에서의 문자열



C언어에서 문자열 처리
  • 문자열은 문자들의 배열 형태로 구현된 응용 자료형.
  • 문자배열에 문자열을 저장할 때는 항상 마지막에 끝을 표시하는 널문자('\0')를 넣어줘야 함.
  • char ary[] = {'a', 'b', 'c', '\0'}; // 또는 char ary[] = "abc";
  • 문자열 처리에 필요한 연산을 함수 형태로 제공함 — strlen(), strcpy(), strcmp() 등
  • C는 아스키 코드로 저장: 한글을 출력할 수 있으나 콘솔의 도움을 받아야 합니다. char* name = "홍길동"; strlen(name) → 6(바이트 수)
Java에서 String 클래스에 대한 메모리 배치 예
  • 문자열 데이터를 저장, 처리해주는 클래스를 제공함 — String str = "abc"; // 또는 String str = new String("abc");
  • 문자열 처리에 필요한 연산을 연산자, 메소드 형태로 제공 — +, length(), replace(), split(), substring() …
  • Java는 유니코드(UTF-16, 2-Byte)로 저장: "홍길동".length() → 3






2-4Python에서의 문자열 처리


  • char 타입 없음 — 텍스트 데이터의 취급 방법이 통일되어 있음.
  • Python은 문자 하나도 길이 1인 문자열입니다(문자열과 unicode 구분이 없습니다).
  • 유니코드(UTF-8) 기반이라 어떤 언어나 기호도 동일한 방식으로 처리됩니다. len("홍길동") → 3
  • 문자열 기호: '(홑따옴표), "(쌍따옴표), '''(홑따옴표 3개), """(쌍따옴표 3개)
  • + 연결(Concatenation) — 문자열 + 문자열: 이어 붙여주는 역할
  • * 반복 — 문자열 * 수: 수만큼 문자열이 반복
  • 문자열은 시퀀스 자료형으로 분류되고, 시퀀스 자료형에서 사용할 수 있는 인덱싱, 슬라이싱 연산들을 사용할 수 있음.
  • 문자열 클래스에서 제공되는 메소드: replace(), split(), isalpha(), find() …
  • 문자열은 튜플과 같이 요소값을 변경할 수 없음(immutable).

4-2고지식한 알고리즘 (Brute Force)



본문 문자열을 처음부터 끝까지 차례대로 순회하면서 패턴 내의 문자들을 일일이 비교하는 방식으로 동작. "한 칸 이동, 비교"를 반복합니다.
  • 본문의 비교위치 i, 패턴의 비교위치 j
  • 일치하면 i, j 증가
  • 실패하면 i는 이전 시작위치 다음으로, j는 맨 앞으로 초기화
시간 복잡도
최악의 경우 시간 복잡도는 텍스트의 모든 위치에서 패턴을 비교해야 하므로 O(MN)이 됨. 길이가 10,000인 문자열에서 길이 80인 패턴을 찾는다고 할 때, 최악의 경우 약 10,000×80 = 800,000번의 비교가 일어납니다.

4-4KMP 알고리즘


  • 불일치가 발생한 텍스트 스트링의 앞 부분에 어떤 문자가 있는지를 미리 알고 있으므로, 불일치가 발생한 앞 부분에 대하여 다시 비교하지 않고 매칭을 수행
  • 패턴을 전처리하여 배열 next[M]을 구해서 잘못된 시작을 최소화함 — next[M]: 불일치가 발생했을 경우 이동할 다음 위치
  • 예) 텍스트에서 abcdabc까지는 매치되고, e에서 실패한 상황 — 패턴의 맨 앞의 abc와 실패 직전의 abc는 동일함을 이용할 수 있음 → 실패한 텍스트 문자와 P[4]를 비교
  • 시간 복잡도: 패턴 길이 M 전처리 O(M), 텍스트 길이 N 검색 O(N) → O(M+N)

4-5보이어-무어 (Boyer-Moore) 알고리즘


  • 오른쪽에서 왼쪽으로 비교
  • 대부분의 상용 소프트웨어에서 채택하고 있는 알고리즘
  • 실제 검색에서 매우 빠른 성능
  • 패턴의 오른쪽 끝에 있는 문자가 불일치하고 이 문자가 패턴 내에 존재하지 않는 경우, 이동 거리는 무려 패턴의 길이만큼이 됨
  • 오른쪽 끝에 있는 문자가 불일치하고 이 문자가 패턴 내에 존재할 경우 — 패턴에서 일치하는 문자를 찾아서 그 위치가 맞도록 점프 (skip 배열)
  • 앞의 두 매칭 알고리즘들의 공통점은 텍스트 문자열의 문자를 적어도 한번씩 훑는다는 것. 보이어-무어 알고리즘은 텍스트 문자를 다 보지 않아도 되며, 일반적으로 O(n)보다 시간이 덜 든다고 알려져 있습니다.
  • 최악의 경우 수행시간 Θ(mn). 입력에 따라 다르지만 일반적으로 Θ(n)보다 시간이 덜 듦. 실제로는 불일치 문자 휴리스틱과 일치 접미부 휴리스틱을 함께 사용합니다.

String 확인문제


1. 문자열 자료형에 대한 설명으로 옳은 것은?
  1. 리스트로만 표현할 수 있다.
  2. 숫자와 동일한 연산자만 사용할 수 있다.
  3. 변경 가능한(mutable) 자료형이다.
  4. 문자열은 순서가 있는 자료형이며 변경할 수 없다.
정답: 문자열은 순서가 있는 자료형이며 변경할 수 없다 — 인덱싱, 슬라이싱이 가능한 순서가 있는 자료형입니다. 하지만 값을 바꿀 수 없습니다(immutable).
2. 유니코드 인코딩 UTF-8에 대한 설명으로 틀린 것은?
  1. UTF-8은 가변 길이 인코딩이다.
  2. 영어 알파벳은 UTF-8에서 1바이트로 표현된다.
  3. 전 세계 대부분의 문자와 호환된다.
  4. 고정 길이 인코딩으로 4바이트로 표현한다.
정답: 고정 길이 인코딩으로 4바이트로 표현한다 — 4바이트 고정으로 인코딩하는 방식은 UTF-32입니다.
3. text = "Python"; print(text[1:4]) 의 결과는?
  1. Pyt
  2. yth
  3. ytho
  4. tho
정답: yth — 슬라이싱은 시작 인덱스 포함, 끝 인덱스 미포함.
4. 문자열 s = "Apple"이 있을 때, s[-2]의 값은?
  1. 'p'
  2. 'l'
  3. 'e'
  4. 'A'
정답: 'l' — 음수 인덱스는 뒤에서부터 셉니다. -1은 'e', -2는 'l' 입니다.
5. 문자열 replace() 메서드의 설명으로 바른 것은?
  1. 대소문자를 자동으로 구분하지 않는다.
  2. 원래 문자열을 직접 변경한다.
  3. 새로운 문자열을 반환한다.
  4. 문자열의 길이를 변경할 수 없다.
정답: 새로운 문자열을 반환한다 — 문자열은 immutable이므로, replace()는 원래 문자열을 변경하지 않고 새로운 문자열을 반환합니다.
6. 다음 중 문자열을 숫자로 변환할 수 없는 경우는?
  1. "42"
  2. "3.14"
  3. "123"
  4. "3.14.15"
정답: "3.14.15" — 숫자 형식이 잘못되어 int()나 float()로 변환할 수 없습니다.
7. 문자열 "Hello World"에서 'o' 문자가 처음 등장하는 인덱스를 반환하는 메서드는?
정답: find() (index()도 가능) — find()는 특정 문자가 없으면 -1을 반환합니다.
8. "banana"라는 문자열에서 'a'의 개수를 세기 위한 메서드는?
정답: count() — 문자열에서 특정 문자가 몇 번 나오는지 셉니다. 'banana'.count('a') → 3
9. text = "hello python"; print(text.upper()) 의 실행 결과는?
정답: HELLO PYTHON — upper()는 문자열의 모든 알파벳을 대문자로 바꿉니다.
10. text = "apple"; r_text = text[ ] — 역순으로 만드는 슬라이싱 표현식은?
정답: [::-1] — 슬라이싱의 세 번째 인자(step)를 -1로 주면 역순이 됩니다.
11. text = "  Hello  "; result = text.strip() 의 result는?
정답: 'Hello' — strip()은 문자열의 앞뒤 공백을 제거합니다. 중간 공백은 제거하지 않습니다.
12. text = '-'.join(['A', 'B', 'C']); print(text) 의 결과는?
정답: A-B-C — join()은 리스트의 각 요소 사이에 지정한 문자열을 삽입해 하나의 문자열로 만듭니다.

압축 (RLE)같은 값이 몇 번 반복되는지로 표현






이 문서의 큰 줄기


  • 메모리는 숫자만 저장하므로 문자 ↔ 숫자 약속(코드 체계)이 필요하다 — ASCII(7bit) → 확장 ASCII(8bit) → 유니코드.
  • 같은 유니코드라도 저장 방식(UTF-8/16/32, Endian)이 다르면 깨진다 — 읽고 쓰는 인코딩을 맞춰야 한다.
  • 파이썬 문자열은 immutable 시퀀스 — 수정하려면 리스트로 바꾸거나 새 문자열을 만든다.
