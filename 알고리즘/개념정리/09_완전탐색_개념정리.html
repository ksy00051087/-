3-1순열과 중복순열


  • 순열: 서로 다른 N개에서, R개를 중복 없이, 순서를 고려하여 나열하는 것
  • 예시) 3개에서 2개를 뽑아 만드는 순열 — [0] [1] [2]로 구성된 3장의 카드가 다량으로 있을 때
  • 이 중에 2장을 뽑아, 중복순열을 나열합니다: [0 0] [0 1] [0 2] [1 0] … [2 2] → 3² = 9가지
  • 이 중에 2장을 뽑아, 순열을 나열합니다: [0 1] [0 2] [1 0] [1 2] [2 0] [2 1] → 3P2 = 6가지






3-2중복 순열 소스코드 — [0 0] ~ [2 2] 까지 출력


path = []
def KFC(x):
    if x == 2:          # 2번 재귀호출 되었고, 이제 바닥에 도착했으니 출력하는 코드를 수행
        print(path)
        return
    for i in range(3):
        path.append(i)  # 선택 기록
        KFC(x + 1)      # 재귀호출 됨. 그리고 돌아오면 코드가 계속 진행되어
        path.pop()      # 선택 취소 (다음 i를 위해)

4-1주사위 N개를 던져 눈의 합이 10 이하인 경우만 출력


  • 방법 1 — 모든 경우를 탐색하지만, 출력만 하지 않는 방법: 위 소스코드는 모든 경우에 대해 탐색을 하고 합이 10이 넘어가는 수는 출력만 생략 (느린 성능)
  • 방법 2 — 가지치기: 답이 아닌 것에 대해 즉시 되돌아감. 1 2 3 4 … 처럼 이미 합이 10보다 크면 재귀호출 할 필요가 없다. 누적합이 10 넘어가는 순간 더 탐색할 필요 없음

5-2완전탐색 문제 2. Baby-gin


  • 0~9 사이의 숫자 카드에서 임의의 카드 6장을 뽑았을 때, 3장의 카드가 연속적인 번호를 갖는 경우를 run, 3장의 카드가 동일한 번호를 갖는 경우는 "triplet" 이라고 합니다. 6장의 카드가 run과 triplet로만 구성된 경우를 baby-gin으로 부릅니다.
  • 6자리 카드 번호를 입력 받고, 완전탐색으로 baby-gin 여부를 판단하는 프로그램을 작성
  • 풀이 힌트 1. 고려할 수 있는 모든 경우의 수 생성하기: 6개의 카드로 만들 수 있는 모든 순서를 나열 = "순열" 코드를 작성합니다. 예) 입력으로 [2, 3, 5, 7, 7, 7]을 받았을 경우 순열 생성
  • 풀이 힌트 2. 검사하는 함수를 제작하여 하나씩 테스트: 앞 3자리가 run 또는 triplet이면서, 뒤 3자리가 run 또는 triplet이면 True를 리턴합니다.
  • 예) 054060 → 한 개의 run과 한 개의 triplet이므로 역시 baby-gin 입니다. (456, 000) / 101123 → 한 개의 triplet(111)이 존재하나, 나머지 023이 triplet, run이 아닙니다. / 123이 run이면 나머지 011이 triplet, run이 아닙니다.

4. 재귀 함수를 사용하는 완전탐색에서는 매 단계마다 어떤 방식으로 선택을 이어가나요?
정답: 현재 단계 선택 후, 다음 단계로 재귀 호출
5. 완전탐색의 시간 복잡도가 급격히 증가하는 주된 이유는?
  1. 조건 비교가 어려워서
  2. 반복문 대신 재귀를 사용해서
  3. 모든 경우를 탐색하기 때문
  4. 배열 접근이 느려서
정답: 모든 경우를 탐색하기 때문
6. 다음 중 재귀를 사용한 완전탐색 코드의 종료 조건으로 적절한 것은?
  1. 함수가 세 번 호출되었을 때
  2. 현재 선택한 조합이 중복되었을 때
  3. 스택이 비었을 때
  4. 선택한 원소의 수가 목표 개수에 도달했을 때
정답: 선택한 원소의 수가 목표 개수에 도달했을 때 — 일반적으로 목표 깊이 또는 선택 개수 도달 시 종료합니다.
7. 반복문으로 순열을 구현하기 어려운 이유는 무엇인가요?
정답: 선택한 요소를 제외한 나머지를 재귀적으로 탐색해야 하기 때문 — 순열은 요소의 순서까지 고려하므로, 매 단계마다 선택한 값을 제외하고 다시 탐색해야 합니다.
8. 부분집합의 합 문제에 가장 자연스러운 방법은?
  1. 정렬
  2. 재귀 호출 기반 부분집합 생성
  3. 이진 탐색
  4. 해시
정답: 재귀 호출 기반 부분집합 생성
9. 가지치기를 적용했을 때의 효과는?
  1. 탐색 결과가 정확하지 않을 수 있다
  2. 탐색 속도는 느리지만 모든 경우를 확인한다
  3. 조건에 따라 탐색을 중단하여 성능을 높인다
  4. 메모리를 더 쓴다
정답: 조건에 따라 탐색을 중단하여 성능을 높인다
10. 완전탐색이 적합한 문제는?
  1. 정렬된 리스트에서 특정 값을 찾는 문제
  2. 가능한 모든 조합 중에서 조건을 만족하는 것을 찾는 문제
  3. 최단 경로 문제
  4. 정렬 문제
정답: 가능한 모든 조합 중에서 조건을 만족하는 것을 찾는 문제
11. 완전탐색이 부적절한 경우는?
  1. 5명 중 2명 뽑기
  2. 주사위 3개 던지기
  3. 50명 중 25명을 뽑는 최적 조합 찾기
  4. 카드 5장 나열
정답: 50명 중 25명을 뽑는 최적 조합 찾기 — 경우의 수(50C25 ≈ 1.26×10¹⁴)가 너무 많아 계산 시간이 폭발적으로 증가합니다.
12. 가지치기(Pruning)의 정의로 옳은 것은?
  1. 모든 경우의 수를 끝까지 탐색하는 방법
  2. 조건에 맞는 결과만 출력하는 방법
  3. 유망하지 않은 경로를 조기에 탐색 종료하는 전략
  4. 반복문 없이 탐색을 수행하는 전략
정답: 유망하지 않은 경로를 조기에 탐색 종료하는 전략

핵심 키워드


키워드설명
재귀 호출현재 단계에서 하나의 선택을 한 후, 다음 단계로 넘어가기 위해 자기 자신을 호출함. 각 호출에는 기저 조건이 존재하여 더 이상 진행하지 않고 종료되는 지점을 명확히 설정해야 함 — 깊이가 조건을 만족하면 return으로 종료함
순열 / 중복순열각각 재귀를 통해 쉽게 구현 가능하며, 호출 흐름이 자연스럽게 트리 형태로 확장 — 순열은 used 배열
가지치기모든 경우를 다 볼 필요 없이, 중간에 조건을 만족하지 않으면 그 경로는 탐색하지 않음. 예: 주사위 눈의 합이 특정 값을 초과한 경우 return 조기 종료. 효율적인 완전탐색을 위해 반드시 필요
재귀 트리 · 백트래킹 흐름각 호출이 완료되면 이전 호출로 되돌아가며, 전체 탐색이 마무리됨. 이를 통해 함수의 흐름과 선택 분기 과정을 체계적으로 분석 가능






이 문서의 큰 줄기


  • for문의 개수를 입력(N)이 정하면 → 재귀(lev, 기저 조건 lev == N).
  • append → 재귀 → pop: 선택하고, 내려가고, 되돌린다. 순열은 여기에 used가 더해진다.
  • 완전탐색의 비용 = 재귀 트리의 노드 수 → 가지치기로 트리를 잘라낸다.
